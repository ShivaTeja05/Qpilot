# Digest 1 — Note 16: Deployment and adoption reality

**Method caveat stated by the note itself:** web search was unavailable; everything came from direct fetches of primary sources named from memory. ## A. How this corner works

Six roles decide whether a tool is used: the bench scientist at an instrument PC they do not own, the PI who pays, the core-facility director working to SOPs, the RSE on a fixed-term contract, the IT/security officer, and the funder/journal. Lifecycle: discover → install ("the first 15 minutes decide everything") → first result → trust → standardise → sustain. Instrument PCs are Windows-only: CFX Maestro needs Windows 10 64-bit, Secure Boot disabled, admin login for a USB install, and data leaves by USB stick or e-mailed .pcrd (https://www.bio-rad.com/webroot/web/pdf/lsr/literature/10000126764.pdf); Thermo tells users to consult Service before downloading anything to a controller PC (https://www.thermofisher.com/us/en/home/technical-resources/software-downloads/applied-biosystems-7500-real-time-pcr-system.html); Windows 10 support ended 14 October 2025 (https://learn.microsoft.com/en-us/lifecycle/products/windows-10-home-and-pro). An ELN field study found "Lab computers were often offline and tied to specific instruments" (https://doi.org/10.1186/s13321-017-0221-3). Open tools fail measurably: of 98 tools, 28% could not be installed within 2 h and 51% were "easy" (≤15 min) (https://journals.plos.org/plosbiology/article?id=10.1371/journal.pbio.3000333); 25.7% of 2,396 web tools were unreachable on day one with a "half-lifetime of 10 years" (https://academic.oup.com/nar/article/48/22/12523/5996215); for 54% of NAR services "no successor has been found" (https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0024914). Cores: 72% lack a system to identify raw data behind published figures (n = 253, 19 countries) (https://elifesciences.org/articles/62212). Funding: CZI EOSS has run six cycles (~US$47M, the note's own sum) with none open (https://chanzuckerberg.com/eoss/); JOSS is free and needs six months of public history (https://joss.readthedocs.io/en/latest/review_criteria.html). Price anchors: Prism US$260/yr academic (https://www.graphpad.com/how-to-buy); Clarida €8–15/experiment (https://clarida.bio/pricing).

## C. Discoveries (note's rank order = impact × feasibility × fit)

### D1. Zero-admin distribution matrix + "first result in 15 minutes on a locked-down PC" acceptance test
- **Persona:** PhD student with no-admin university laptop, offline shared instrument PC, Mac at home; core director wanting one artefact to qualify once and copy to five PCs.
- **Pain evidence:** 28% of tools not installable in 2 h; "Avoid commands that require root privileges" (https://journals.plos.org/plosbiology/article?id=10.1371/journal.pbio.3000333); vendor install needs admin + USB (https://www.bio-rad.com/webroot/web/pdf/lsr/literature/10000126764.pdf); Fiji "'Program Files' not recommended!" (https://imagej.net/software/fiji/downloads); QuPath portable zip "should not need such privileges" (https://qupath.readthedocs.io/en/stable/docs/intro/installation.html); Bioconda has no Windows builds (https://bioconda.github.io/); HF Gradio Spaces now need a paid plan to create (https://huggingface.co/docs/hub/spaces-overview).
- **What exists / why insufficient:** Clarida and web tools (need network); vendor software (Windows, admin, per-seat); academic R/Python scripts. No qPCR tool ships a portable Windows build or per-user installer.
- **Feature:** Five artefacts from one CI pipeline: (a) PyPI wheel with Trusted Publishing attestations (https://docs.pypi.org/attestations/) installed via `uv tool install qpilot` / `uvx qpilot` (https://docs.astral.sh/uv/guides/tools/); (b) conda-forge feedstock, not Bioconda (https://conda-forge.org/docs/maintainer/adding_pkgs/); (c) Windows portable zip (embeddable Python, https://docs.python.org/3/using/windows.html) with `--portable` mode; (d) per-user NSIS installer ("RequestExecutionLevel user") signed via SignPath Foundation (https://signpath.org/); (e) macOS zip/pkg with documented Gatekeeper steps (https://developer.apple.com/developer-id/). Plus `qpilot doctor` (env, checksums, offline egress test, example run) and `qpilot quickstart`. Acceptance: clean Win10/11 VM as standard user, download → first Decision Card ≤15 min, ≤3 commands, zero UAC prompts, zero network.
- **Feasibility:** Python per-user/embeddable builds PSF-licensed. Packager candidates — licences **NOT re-verified in the note**: pynsist (MIT) + NSIS (zlib), Briefcase (BSD-3), Nuitka (Apache-2.0), conda `constructor` (BSD-3); "avoid PyInstaller's GPL-with-exception bootloader given the 'no GPL in the distribution' rule" (also unverified). Effort: wheel+attestations 1 day; conda-forge 1–2 days + review wait; portable zip 3–5 days; signed installer 3–5 days + SignPath onboarding; CI Windows VM test 3–5 days. Hardest: antivirus/SmartScreen false positives before reputation accrues; keeping lxml/numpy wheels consistent across five forms.
- **Why qPilot:** pure Python, permissive deps (rdmlpython MIT), everything is a file, CLI + MCP already exist.
- **Risks/confidence:** five artefacts for two devs (mitigate: one `pyproject.toml`, one CI matrix); HF paid-plan change. Confidence: **high** on no-admin as precondition; **medium** on tool choices. Rank 1.

### D2. "Analysed — two decisions need you": watched-folder analyser with Slack/Teams/e-mail digests bound to the record hash
- **Persona:** technician starting a run at 16:30; postdoc running six plates over a week; core analyst processing client runs daily.
- **Pain evidence:** CFX Maestro e-mails run completion with .pcrd and PDF attached, suggests phone e-mail-to-SMS (https://www.bio-rad.com/webroot/web/pdf/lsr/literature/10000126764.pdf); nf-core `--hook_url` for "MS Teams and Slack" (https://raw.githubusercontent.com/nf-core/rnaseq/3.14.0/nextflow_schema.json); ELN users want auto-capture 81%, enter-once 74% (https://doi.org/10.1186/s13321-017-0221-3).
- **What exists:** vendor e-mail of raw data; Thermo Connect cloud (details not fetched); manual next-morning analysis.
- **Feature:** `qpilot watch <folder> --study <id> --notify <channel>` — per-user background job (Task Scheduler / launchd) detecting size-stable exports, importing, re-running study + robustness grid, posting digest: plates analysed, Decision Cards by impact, GRADE-style confidence with reasons, "what changed", record root hash + version, deep link `qpilot://study/<id>/card/<n>`. Channels: Slack webhook, Teams Adaptive Card, SMTP, OS notifications. Privacy default: counts/titles/hashes only, sample names tokenised (D3). Every post written to the record as a `notification` event. MCP: agent calls `qpcr_study` then `qpilot notify`.
- **Feasibility:** stdlib + `requests`; polling (works on network shares). Effort: watch/import/digest 3–5 days; adapters 2 days; deep links/tray 3–5 days. Hardest: detecting "export finished" for multi-file/partial writes; per-user scheduled tasks on managed PCs without admin (unverified).
- **Why qPilot:** impact-ranked cards + Study Confidence are the digest content; hash chain gives integrity anchor; MCP server lets an agent be the watcher.
- **Risks/confidence:** notification fatigue (send only on conclusion-affecting cards); identifier leakage (D3 tokenisation). Confidence: **medium-high** on value, **medium** on webhook uptake in wet labs. Rank 2.

### D4. Core-facility qualification kit: `qpilot qualify`, traceability stamps, SOP template, client report
- **Persona:** qPCR core director with 2–4 staff, fee-for-service, asked weekly which raw data produced a figure.
- **Pain evidence:** 72% cannot identify raw data; QC of analysis 40%/10%; DMPs 30%; "difficulty with software cost and implementation" (https://elifesciences.org/articles/62212); staff work "according to standard operating procedures" (https://doi.org/10.15252/embr.201642857); vendors sell Part-11 editions with audit trails and hardware keys (https://www.bio-rad.com/en-us/product/cfx-maestro-software-for-cfx-real-time-pcr-instruments?ID=OKZP7E15).
- **What exists:** vendor Security Editions (single-plate, per-seat, hardware key); LIMS/ELN (no analysis provenance); Clarida Center audit log "on request" (https://clarida.bio/pricing). None produces an IQ/OQ document or client-verifiable cross-plate record.
- **Feature:** (a) `qpilot qualify` runs RDML-consortium benchmark + example studies, compares to published tolerances, captures environment, writes `IQ-OQ-<date>.pdf/.md` signed by record hash; (b) traceability stamp `record:<hash-prefix> v<n>` on every figure/table/methods paragraph + `qpilot verify <file>`; (c) SOP template (Diátaxis how-to, https://diataxis.fr/) following the eLife four checkpoints; (d) one-page client report (decisions, actor, confidence, robustness agreement, hash, how to verify); (e) 2-hour training module from the classroom worksheet.
- **Feasibility:** builds on existing benchmark validation; ReportLab/WeasyPrint (BSD, not re-verified). Effort: qualify 1 week; stamps+verify 3–5 days; templates 3–4 days; training 2–3 days. Hardest: acceptance tolerances strict enough to mean something, loose enough across OS/BLAS builds.
- **Why qPilot:** whole-study + hash-chained decision log is what cores lack; actor field = "who decided"; Study Confidence = the missing QC-of-analysis.
- **Risks/confidence:** cores read "qualification" as regulatory validation (state research-use-only); instrument PCs can't run it (use D5). Confidence: **high** on pain, **medium** on cores' capacity to adopt. Rank 4.

### D5. Two-machine, offline-first workflow: single-file verifiable study exchange over USB/e-mail
- **Persona:** anyone with an offline/locked instrument PC; collaborator with nothing installed.
- **Pain evidence:** "On connected CFX Duet systems, data can only be transferred via a USB drive" (https://www.bio-rad.com/webroot/web/pdf/lsr/literature/10000126764.pdf); offline instrument PCs (https://doi.org/10.1186/s13321-017-0221-3); Windows 10 EoS; Stanford "supported OS" rule (https://uit.stanford.edu/guide/securitystandards).
- **What exists:** vendor binaries moved by hand; e-mailed Excel; web uploads; nothing verifies integrity or carries decisions.
- **Feature:** `qpilot pack <study>` → `study.qpilot` zip (RDML + results, hash-chained log, versions, checksums, optional raw vendor files, Trust Pack hash, `MANIFEST.json`); `qpilot verify` (CLI, standalone verifier in portable zip, browser-only JS page); `qpilot import` detects duplicates/partial transfers; `--portable` runs from USB on instrument PC. MCP exposes pack/verify.
- **Feasibility:** stdlib (zipfile, hashlib). Effort: pack/import 3–4 days; verify 3–5 days; portable paths 2 days. Hardest: Mark-of-the-Web/SmartScreen on USB executables; AV heuristics.
- **Why qPilot:** everything already a checksummed file; byte-for-byte re-runnability; workspace locks anticipate two actors.
- **Risks/confidence:** some IT policies discourage USB (format works over share/e-mail). Confidence: **high**. Rank 5.

## A. How this corner works

A bench scientist receives a DEG table from a sequencing core, picks a handful of genes and reference genes, runs one or two plates, computes ΔΔCq and writes "confirmed by qRT-PCR"; RT-qPCR is "still considered the method of choice for validation" (https://pmc.ncbi.nlm.nih.gov/articles/PMC5431503/). Whether validation is needed is contested: Coenye argues RNA-seq is "robust enough to not always require validation" (https://pmc.ncbi.nlm.nih.gov/articles/PMC7823214/). Benchmarks: 15.1–19.4% of genes non-concordant, 1.8% severely, concentrated in small, few-exon, low-expressed genes (https://pmc.ncbi.nlm.nih.gov/articles/PMC5431503/); SEQC used 843 TaqMan and 20,801 PrimePCR assays, Spearman 0.83 vs TaqMan (https://pmc.ncbi.nlm.nih.gov/articles/PMC4321899/). Reference genes are chosen by habit: 128 vertebrate studies used 1.23 references on average, 93/128 (>72%) used GAPDH/ACTB/18S alone, 15% tested a panel (https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0141853). Hand-off failure: 30.9% of 11,117 articles with Excel gene lists (2014–2020) contained auto-converted symbols (https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1008984); 19.6% in 2005–2015 (https://link.springer.com/article/10.1186/s13059-016-1044-7); 19.5% in May 2026 (https://ziemann-lab.net/public/gene_name_errors/Report_2026-06.html). HT panels: Biomark 96.96 = 9,216 reactions (https://www.standardbio.com/products/instruments/biomark-x9); OpenArray 3,072 reactions/plate (https://www.thermofisher.com/us/en/home/life-science/pcr/real-time-pcr/real-time-pcr-instruments/quantstudio-12k-flex-real-time-pcr-system.html); neither in RDML's instrument list (https://rdml.org/instruments.html); the only open reader is HTqPCR, 17 years in Bioconductor (https://bioconductor.org/packages/release/bioc/html/HTqPCR.html). Pre-amplification beyond 18 cycles fails (57%/46% success at 21/24) (https://pmc.ncbi.nlm.nih.gov/articles/PMC4365555/). Panel sizes in read papers: 7 to 115 genes. Bench time 1–2 days (estimate).

## C. Discoveries (note's rank order)

### D1. "RefSeek": reference-gene candidates from the lab's own sequencing, feeding qPilot's geNorm step
- **Persona:** bench scientist/core analyst with a count or TPM matrix (6–40 samples) from the same tissue/treatment, about to put GAPDH and ACTB on the plate. Every RNA-seq → qPCR transition.
- **Pain evidence:** 87% single reference; 72% GAPDH/ACTB/18S; 15% tested (https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0141853). Data-derived candidates beat classics everywhere read: tomato ARD2/VIN3 geNorm M 0.092 vs GAPDH 0.204, GAPDH "normalizing with it falsely inflated ARD2 expression" (https://pmc.ncbi.nlm.nih.gov/articles/PMC5357963/); genome-wide ACTB rank 57, GAPDH rank 139 (https://pmc.ncbi.nlm.nih.gov/articles/PMC1976390/); PBMC EIF2S3/SF3B1 over GAPDH (https://pmc.ncbi.nlm.nih.gov/articles/PMC7778946/); "three-fold bias in 25% of results" with one reference (https://pmc.ncbi.nlm.nih.gov/articles/PMC3825189/).
- **What exists:** HRT Atlas (web, JS-only, code MIT, data terms unstated, tissue-level); RefGenes/Genevestigator (microarray, academic registration, domain unresolved); Joshi Gini (MATLAB, unlicensed); ERgene (MIT on PyPI, "academic non-commercial" in paper); findRGs (Ruby, unlicensed); scMerge (GPL-3). None reads the lab's own matrix inside a qPCR tool.
- **Feature:** Input gene × sample matrix (counts or TPM, auto-detected), sample sheet, target list, species. Deterministic per-gene rules: (a) ≥1 RPKM/TPM in every sample; (b) SD log2(TPM+1) < 0.5 candidate / < 1 HK; (c) max/mean log2 < 2 (all HRT Atlas rules, https://pmc.ncbi.nlm.nih.gov/articles/PMC7778946/); (d) CV; (e) Gini (https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1010295 ; https://www.nature.com/articles/s41598-019-54288-7); (f) group-effect test (ANOVA/Kruskal–Wallis) — any group effect excludes; (g) expression-band ±2 log2 of targets; (h) exclude pseudogene-bearing, rRNA, mito; (i) co-regulation screen r > 0.9. Rank by Score Product; show top 12–20 with atlas membership and assay availability (PrimerBank, GETPrime REST, HRT Atlas primers). Decision Card e.g. "GAPDH log2FC −0.9 between groups, p = 0.004". Record: matrix hash, parameters, all metrics, chosen set, reason. MCP: `qpcr_reference_candidates(matrix_path, samplesheet_path, targets, species, band=2.0)`.
- **Feasibility:** numpy/pandas; acceptance: reproduce Pombo ranking, HRT Atlas PBMC case, SEQC classics' instability (GSE47792). Licences: HRT Atlas data unstated (citation-only); Eisenberg no terms; HGNC no restrictions. Effort 1–2 weeks engine + 1 week lookups (REST off by default). Hardest: normalisation units, small n (<4/group makes rule f meaningless).
- **Why qPilot:** already owns geNorm M/V, reverse-normalisation guard, cards, record, MCP.
- **Risks/confidence:** RNA-seq stability ≠ qPCR stability (pig-liver counter-example, https://pmc.ncbi.nlm.nih.gov/articles/PMC3072958/) — must always end in the geNorm step. Confidence: **high** on pain and maths; **medium** on how often a matched matrix exists. Rank 1.

### D2. Concordance Report bound to facts
- **Persona:** scientist writing the validation paragraph; reviewer; PI deciding on a discordant story gene.
- **Pain evidence:** correlation "is always misleading" for method comparison (https://pmc.ncbi.nlm.nih.gov/articles/PMC4470095/); rigorous studies use direction + fold thresholds, sensitivity/PPV, RMSD 1.18–2.50 (https://link.springer.com/article/10.1186/s12864-015-1767-y); concordance 75% above median vs 20–40% below (https://pmc.ncbi.nlm.nih.gov/articles/PMC4243706/); edgeR PPV 90% vs Cuffdiff2 39%.
- **What exists:** Excel/Prism scatter; HTqPCR has no cross-platform report; no open Bland–Altman on log2FC with stratification.
- **Feature:** Inputs: qPilot per-gene log2 quantities with CI; DEG table(s). Definitions locked before results: DE |log2FC| > 1; validated same direction and qPCR FC > 1.25 or < 0.80; severe ΔFC > 2 or opposite. Outputs: (a) counts with binomial CIs vs Everaert 15–19%/1.8% (https://pmc.ncbi.nlm.nih.gov/articles/PMC5431503/); (b) Bland–Altman bias, LoA, proportional-bias slope, Passing–Bablok; (c) stratification by expression quartile, gene length/exons; (d) per-discordant-gene risk flags; (e) all recomputed across qPilot's robustness grid ("unchanged in 23 of 24 variants"); (f) pipeline comparison; (g) methods paragraph with fact ids; (h) explicit proteomics caveat (RNA–protein ratios 200 to 220,000, https://pmc.ncbi.nlm.nih.gov/articles/PMC5081484/). MCP: `qpcr_concordance(study_id, deg_table_path, definitions)`.
- **Feasibility:** numpy/scipy, 1–2 weeks; acceptance: SEQC PrimePCR GPL18522 + TaqMan GPL4097 vs GSE47792 RNA-seq reproducing Everaert. Hardest: identifier matching; defaults when DEG table lacks expression columns.
- **Why qPilot:** robustness engine makes the claim honest; record freezes definitions; fact ids stop invented r values.
- **Risks/confidence:** reviewers still want "the correlation" (provide, labelled); over-strict defaults. Confidence: **high**. Rank 2.

- **Feature:** (a) **Symbol gate** — date regex `^\d{1,2}-(Jan|Feb|Mar|Sep|Oct|Nov|Dec)$`, float pattern `\d\.\d+E\+\d+`, HGNC complete-set TSV shipped (no restrictions, https://www.genenames.org/about/; updated Tue/Fri, https://www.genenames.org/download/); ambiguous cases (Mar-01 → MARC1 or MARCHF1) as Decision Cards; Ensembl ID as primary key. # Digest 3 — W2 Run Gate and Lab Memory specification

**Status:** synthesis of six notes (01, 02, 06, 09, 14, 15); product horizon 6–18 months, "nothing here is hackathon scope". One-paragraph thesis: research qPCR has controls on the plate but no *rules*, no *memory* of assay/instrument/lot behaviour, and no way to decide whether a failed control matters; clinical labs solved this with typed controls, run-validity rules, Levey-Jennings and lot bridging (https://www.westgard.com/mltirule.htm ; https://www.westgard.com/lesson12.htm ; https://pmc.ncbi.nlm.nih.gov/articles/PMC2901657/) sold as closed middleware (https://www.ugentec.com/fastfinder/qc). Run Gate and Lab Memory are one system: Gate thresholds are learned from Memory; Memory alerts are delivered as Gate cards.

## Structure
- **§0 Terms** (RDML sample types `unkn/ntc/nac/std/ntp/nrt/pos/opt`; `ref` is a *target* type; booleans `interRunCalibrator`, `calibratorSample`; LinRegPCR N0 = Nq / E^Cq; Levey-Jennings; Westgard; BLOD/BLOQ; TOST).
- **§A Unified data model** — A.1 objects/keys; A.2 identity; A.3 assay passport; A.4 instrument passport; A.5 lot passport + side-car; A.6 build pipeline; A.7 local storage.
- **§B Rule pack** — B.0 YAML format; B.1 gate rules; B.2 trending (Westgard); B.3 lot rules; B.4 run-factor rescue; B.5 regulatory-SOP packs.
- **§C Triage** — C.1 definitions; C.2 consequence test; C.3 cost model; C.4 decision table; C.5 four worked examples.
- **§D Cards and record** — D.1 what the scientist sees; D.2 record fields; D.3 MCP tools; D.4 autonomy matrix.
- **§E Validation plan** — E.1 public datasets; E.2 acceptance tests; E.3 what a lab's own data adds; E.4 build plans.
- **§F Risks** — F.1 what RDML cannot provide; F.2 vocabulary; F.3 source conflicts; F.4 other risks.

## A.1 Objects
`Run` (key `run_hash` = SHA-256 of canonicalised RDML run element, floats rounded to 6 sig. digits), `Well`, `WellFacts` (cq, N0, ampEff, ampEffSE, excl, note, bgFluor, bgFluorSlp, meltTemp…), `Assay`, `Instrument`, `LotRecord` (`<kind>:<manufacturer>:<order>:<lot>`), `ControlMaterial`, `Series` (metric, assay_id, control_id, instrument_id — one point per run), `Event` (lot_change, calibration, lamp, service, software, operator, rule_pack_change), `RulePack/Rule/RuleEval`, `Card/Decision`, `Passport` (kind ∈ assay/instrument/lot/control_material; versioned JSON; `passport_hash` written into every record).

## A.2 Identity rules
- **Assay:** `assay_id = "seq:" + SHA-256(upper(fwd)|upper(rev)|upper(probe1)|upper(probe2))` when RDML `target/sequences` exists; else `"com:" + company + ":" + orderNumber` (TaqMan context-sequence hash usable); else `"name:" + target.id`, which raises a one-time **reconciliation card** ("targets `GAPDH`, `Gapdh_2`, `GAPDH-new` appear in 14 runs; same assay?") stored as an alias table. Most vendor exports carry no sequences, so alias table + side-car are where identity actually lives.
- **Instrument:** RDML `run/instrument` is free text; lab profile maps strings → `instrument_id`; first unmapped string raises a card; serials never leave the machine.
- **Control material:** `pos`/IRC sample matched to `control_id` by (sample name, assay, alias table); unmapped → chart shows "unmapped control", never guesses.
- **Lot:** side-car only; date-range back-fill flagged `lot_source = inferred_from_dates`.

## A.3–A.5 Passports
**Assay passport:** identity; per-run LinRegPCR mean E with SD and n (https://www.ebi.ac.uk/europepmc/webservices/rest/PMC8386043/fullTextXML); learned interval = median and MAD×1.4826 over first ≥10 runs, stored per instrument because E is instrument-dependent (https://www.gene-quantification.de/svec-et-al-pcr-efficiency-bdq-2015.pdf ; https://pmc.ncbi.nlm.nih.gov/articles/PMC4578049/); standard-curve E stored **separately** from LinRegPCR E (standard-curve E runs high with pipetting error, per-curve E runs low with inhibitors — MIQE 2.0 https://academic.oup.com/clinchem/article/71/6/634/8119148 ; Hastings https://pmc.ncbi.nlm.nih.gov/articles/PMC8484782/); calibrator/control Cq and N0; melt fingerprint (product within 1.0 °C, min peak height 0.05, min width 5 °C — rdmlpython MCA defaults); NTC behaviour (MIQE five-cycle rule; Thermo NTC Ct > 38 https://www.thermofisher.com/order/catalog/product/4440888/faqs ; PrimePCR redesign at NTC Cq < 35 https://www.bio-rad.com/sites/default/files/webroot/web/pdf/lsr/literature/Bulletin_6262.pdf); LOD/LOQ (Klymus discrete LOD ≥95% detection, LOQ CV < 35%, effective LOD 1−(1−p)^n; Poisson floor 3 copies); single-copy anchor (10 copies ≈ Cq 35 at E 1.9, https://pmc.ncbi.nlm.nih.gov/articles/PMC8229287/); lot timeline; flags history. Written back into RDML `target` fields (`amplificationEfficiency`, `amplificationEfficiencySE`, `amplificationEfficiencyMethod`, `meltingTemperature`, `detectionLimit`).

**Instrument passport:** identity and events (Thermo calibration cadence: ROI/background/uniformity/dye semi-annually, background monthly; QS3/5 every two years — https://www.ffclrp.usp.br/divulgacao/emu/real_time/manuais/QuantStudio3_5_InstallUseMaint_UG.pdf); per-run control Cq Series; NTC p-chart; baseline distributions; per-run efficiency; uniformity from ≥24 replicate plates (Thermo RNase P criterion (Cq_A − 3σ_A) > (Cq_B + 3σ_B); Bio-Rad "2-fold discrimination with 99.7 % confidence" https://www.bio-rad.com/sites/default/files/webroot/web/pdf/lsr/literature/Bulletin%206323.pdf); verification-plate re-analysis; between-instrument offsets (Ruijter 2015 https://pmc.ncbi.nlm.nih.gov/articles/PMC4822202/).

**Lot passport and side-car:** RDML 1.4 candidate has no element containing "lot", "batch", "barcode" or "reagent" (https://raw.githubusercontent.com/RDML-consortium/rdml-schema/master/RDML_v1_4_CR.xsd). Side-car `labmemory/run_meta/<run_hash>.yaml`, "written by a 10-field prompt at import (defaults carried forward)". The example YAML keys: `schema`, `run_hash`, `instrument_id`, `operator` (optional), `plate_barcode` (optional), `lots.master_mix`, `lots.rt_enzyme`, `lots.rt_batch_id`, `lots.per_assay` (primer_lot / probe_lot / assay_mix_lot keyed by assay_id), `lots.standard` (control_id, lot, nominal_copies_per_ul), `lots.control_material` (sample_name → control_id, lot), `notes`. (The spec says "10-field" but does not enumerate which ten; the YAML shows these keys.) Plus `labmemory/lots.jsonl`. Field precedence: side-car → RDML `sample/annotation` pairs with namespaced names (`qpilot:lot.master_mix`, `qpilot:control_id`, `qpilot:spike_copies`, `qpilot:instrument_id`) → vendor headers → date inference. **RDML extension proposal** for v1.5: a `reagent` element (type, manufacturer, orderNumber, lot, receivedDate, expiryDate) referenced by `run/reagentRef`, `target/reagentRef`, `sample/reagentRef`, plus `run/instrumentSerial` and `run/plateBarcode`; justified by MIQE 2.0 asking for lot numbers and verification "when changing batches".

**Build (A.6):** `qpilot memory build [--workspace DIR] [--since DATE] [--rebuild]`: discover → analyse (rdmlpython with `pcrEfficiencyExl=0.05`, `excludeNoPlateau=True`, `excludeEfficiency="outlier"`, `excludeInstableBaseline=True`) → type and map → derive Gate facts → form Series → evaluate trending → write passports + `memory_manifest.json`. Passports are pure functions: `rebuild` must be byte-identical. 2,000-plate archive ≈ 35 M floats, hundreds of MB parquet, minutes to an hour (estimate). **Storage (A.7):** `labmemory.sqlite`, `curves/<run_hash>.parquet`, passports JSON; nothing transmitted; only `qpilot memory export --anonymised` (serials, operators, barcodes excluded by schema).

## B.2 Trending (Westgard adapted)
Series per (metric, assay, control, instrument): `pos`/IRC Cq and N0, per-target mean E, Tm, baseline level/slope, NTC rate per plate. Baseline: "a minimum of 20 measurements over at least 10 days"; limits ±2 SD and ±3 SD (https://www.westgard.com/lesson12.htm); before 20 points status `provisional`, bands ×1.5, only 1_3s warnings; Shapiro–Wilk normality warn at p < 0.01 (https://pmc.ncbi.nlm.nih.gov/articles/PMC9331565/). Rules verbatim from https://www.westgard.com/mltirule.htm: 1_2s (warning only, never a card), 1_3s (rejection), 2_2s (across and within run), R_4s (within-run only, ≥2 wells), 4_1s (across runs), 10x/8x/12x, 2of3_2s/3_1s/6x/9x when three control wells. Rationale: "±2 SD limits about 5 % of good runs are falsely rejected" (Burd). Additions: p-chart on NTC rate; EWMA (λ = 0.2, L = 3) on E and Tm; change-point at every Event. **A card fires only** when the hit concerns a plate in an open study *and* the robustness engine shows exclusion/correction changes a conclusion; otherwise an FYI line.

## B.4 Run-factor rescue
Ruijter 2015: Y_nj = F_n × (Y_mean + C_j + error); ratio of run factors = geometric mean of ratios over overlapping conditions; nested substitution ("more than 2 rounds … design … clearly incomplete"); N0_corrected = N0 / F_n (https://pmc.ncbi.nlm.nih.gov/articles/PMC4822202/). Alternative: Hellemans IRC correction (https://europepmc.org/article/PMC/PMC1852402). Reimplemented under Apache-2.0; Factor-qPCR licence unstated.

## C.2 Consequence test
A conclusion = per-gene per-comparison direction, whether CI excludes 1, whether effect clears the G-CLAIM tier, plus Study Confidence. The robustness grid is re-run restricted to `consequence_scope` under the hit's options: G-NTC-1 keep / exclude tainted / subtract NTC background; G-REP keep / drop well / drop sample; G-POS and trending keep / exclude plate(s) / run factor / lot offset; G-EFF plate E / passport E / exclude target; G-STD full curve / drop end level / plate-specific LLOQ / pooled curve; BLOQ as 0 / LOQ/2 / censored; G-IPC keep / inhibited / exclude. Result ∈ {`none` (all calls identical, grid agreement changes < 1 cell), `magnitude` (same calls, log2 effect moves more than tier resolution or Confidence drops one level), `flip` (any call changes direction, crosses 1, or crosses tier), `unknown` (study incomplete — re-evaluated automatically when plates arrive)}.

## Cold-start admissions (F.1, E.3)

## Winner and reasoning
**eDNA LOD/LOQ passport (93)** — the only candidate where all four hold at once: (a) published numeric method with CC BY paper (Klymus 2020, 580 Crossref citations: https://dspace.library.uvic.ca/bitstreams/26e02ceb-fd07-486b-b7c1-283f0eb1ea8b/download) plus a US-government public-domain reference implementation and regression data (36 assays, 7 labs); (b) pain quantified by the method's own authors — model choice moves LOD "ranging from 1.07-fold to 8.72-fold"; eDNA studies "rarely report" LOD/LOQ; 1→8 replicates gives mean 11.1-fold drop in effective LOD; (c) a champion with a mandate (USFWS QAPP: curves accepted at E 80–120%, R² ≥ 0.95; "if field blanks are 11, 22 and 33 and 22 is positive … then samples 12–32 will be negated"); (d) the only existing tool is a provisional R script on a GPL-2 dependency. It also builds the "standard-series substrate" (typed standard wells, per-well call, dilution fits, acceptance windows) reused by absolute quant, gene therapy, wastewater and GMO. **Second: Telomere (87)** — highest pain-to-competition ratio (ICC reported in 2 of 25 method-comparison studies, Lindrose 2021; correlation of *change* only r = 0.48, Nettle 2021); reuses most of the expression engine; adds ICC and a plate/well mixed model. Versus source notes: agrees with 08 (eDNA first) and 09 (telomere first); demotes note 10's dPCR from first to "third data kind" on effort and unverified rdmlpython dPCR support. **Sensitivity:** Data weight 0 → eDNA 90, telomere 87, dPCR ties third; Effort 20 → dPCR 73, miRNA 78, top two hold; Community 25 → dPCR second (84) ahead of telomere (82), eDNA still first (92). "The eDNA recommendation is robust to every re-weighting tried."

## Generalisation table (§5.2)
**Generalises as-is:** replicate outlier drop/keep (telomere, eDNA standards, gene-therapy QC); empty-well/non-detect rules → non-detect policy axis (zero, half-LOD, LOQ/2, censored); group cut-offs as robustness axis (Cq ≤ 40, CV thresholds, acceptance windows); impact-ranked cards, autonomy levels, escalation rule ("conclusion-flipping" → "a sample's call flips", "a site's detection flips", "a cohort member crosses a tertile", "an integer copy number changes"); record (hash chain, versions, "no naked numbers", methods paragraph, `qpcr_study`/`qpcr_robustness`/`qpcr_decide`); checklist auto-fill with different item lists (TRN, Klymus/Thalinger, dMIQE, ENGL); GRADE-style confidence with domain reason sets; `qpilot plan` extended to "replicates for an effective LOD" and "ICC for this cohort size".
**Needs new decision kinds:** model-family choice (eDNA LOD; composite curve); plate/run gate (accept / accept with exclusions / reject) — "Note 15's 'Run Gate' is this, and should be built once as a generic rule-pack evaluator"; control negation of a sample range (human-only); calibration bridging (extraction kit / lot vs within-group Z-scoring); constant provenance (partition volume, genome size, conversion factor); cluster assignment/orphan (dPCR multiplex, HRM, allelic discrimination — "the reason those three share an engine").
**Needs new record fields:** standard nominal quantity and lot; sample roles beyond RDML (field blank, hood control, extraction negative, IPC, spike, calibrator, QC DNA, replicate run id, individual id, extraction method); assay passport facts (LOD, LOQ, effective-LOD table, model, CI, history); ICC with CI; plate/well variance components; rule-pack id/version/hash; constants with provenance.
**Does not generalise:** geNorm M/V and reverse-normalisation guard (telomere uses one single-copy gene; eDNA has no reference); ΔΔCq group comparisons and "per-gene consequence"; amplification-curve facts for dPCR partitions; MIQE 2.0 item wording.
