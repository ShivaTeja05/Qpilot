# The qPilot engine

The engine is the part of qPilot that turns an instrument's raw export into numbers a reviewer can check. It is ordinary, deterministic Python: the same file and the same choices always give the same numbers. It calls no language model. Its only network access is the explicit, SHA-256-pinned download of the demo study and the published benchmark tables (`qpilot fetch-demo`). Every number that qPilot shows to a person or a model comes from here.

## The engine, step by step

1. **Open** (`qpilot/io/rdml_io.py`). Reads RDML, the instrument-neutral XML standard for qPCR, plain or zipped, through a hardened parser: no external entities, no network, size and compression-ratio caps.
2. **Curves** (`qpilot/qpcr/curves.py`). Runs LinRegPCR, vendored unchanged, on every plate and returns per-well Cq, efficiency and starting quantity N0. Results are cached by the input file's hash and the settings. [Method card](../methods/linregpcr.md)
3. **Quantities** (`qpilot/qpcr/quant.py`). log2 N0 per sample and gene; a well that never amplified stays missing ("undetermined").
4. **Groups** (`qpilot/qpcr/design.py`). High versus rest by a marker gene's expression (demo: the top 15 % by MYCN), fixed once from the primary control genes.
5. **Control genes** (`qpilot/qpcr/refgenes.py`). geNorm stability M, ranking and pairwise V, giving the recommended set. [Method card](../methods/genorm.md)
6. **Comparison** (`qpilot/qpcr/contrast.py`). Welch's t-test on log2 relative quantities, giving fold change, 95 % confidence interval, p-value and a conclusion. [Method card](../methods/contrast.md)
7. **Alternatives** (`qpilot/qpcr/space.py`). Every reasonable way to analyse the same plates: 31 control-gene subsets × 3 group cut-offs × 2 rules for empty wells = 186 analyses.
8. **Robustness and Decision Cards** (`qpilot/core/`, domain-agnostic). Sweeps the 186 analyses, measures how often each conclusion holds, and turns every choice that can flip a conclusion into a Decision Card for a human.
9. **Proof** (`qpilot/qpcr/validation.py`). `qpilot validate` reproduces the RDML consortium's published benchmark (below).

## The conclusion rule

Every conclusion is shown with the rule that produced it:

> up or down only if p < 0.05 and the change is at least 2-fold; otherwise no call

Two-fold and p < 0.05 are conventions, not laws; the [contrast method card](../methods/contrast.md) says what is and is not claimed.

## Validation

The demo file carries a dilution series of known input on every plate, and the RDML consortium published its own results for those wells. `qpilot validate` compares the engine with three of their tables. The lines below are copied verbatim from the script's output (a test checks them against `validation/validation.json`):

<!-- Generated by `qpilot validate`. Do not edit these three lines by hand; tests/engine/test_docs.py compares them with validation/validation.json. -->
- N0 on 930 standard wells (62 genes) vs RDML-Tools: 99.6 % identical to 4 significant figures, 100.0 % within 5 % (largest difference 0.05 %)
- Dilution-series bias over 62 genes vs LinRegPCR (2013): median |difference| 0.021 (ours 0.961 vs published 0.947 on average)
- Cq on 945 standard wells (63 genes) vs LinRegPCR (2013): offset +0.97 cycles on average (SD 0.17), a change in how LinRegPCR defines Cq, disclosed

The full table, the sources with their SHA-256 hashes, and the genes that could not be matched by name are in [`validation/validation_table.md`](../validation/validation_table.md).

## Try it

```bash
pip install -e .
```

```bash
qpilot fetch-demo
```

```bash
qpilot run --contrast ODC1 --contrast NM23A
```

```bash
qpilot run --contrast ODC1 --contrast NM23A --refs HMBS
```

```bash
qpilot validate
```

The first run analyses 24,576 curves in about 12 seconds; after that the cached curve table loads in well under a second.

## Limitations

- **One gene per plate** in the demo study, so plate effects cannot be separated from gene effects; there is no plate-effect or mixed model.
- **No technical replicates** in the demo: each sample is measured once per gene.
- **No melt-curve analysis** and no kinetic outlier test.
- **One instrument platform:** validated on one published study run on LightCycler 480 with SYBR Green I.
- **Groups are expression-defined:** MYCN-high means the top 15 % by MYCN expression, not the clinical MYCN amplification call.
- **No multiple-testing correction** across the 58 compared genes. The robustness meter measures sensitivity to analysis choices, not significance.
- **Research use only.** Not for clinical or diagnostic use.

## Built vs borrowed

**Borrowed, credited and unchanged**
- LinRegPCR: rdmlpython by the RDML consortium (MIT), vendored at commit `fce7a44`.
- The RDML format and its XML schemas (RDML consortium).
- The geNorm method (Vandesompele et al., 2002), reimplemented from the paper.
- Welch's t-test and the t distribution (SciPy).
- The demo data (Vermeulen et al., 2009; Ruijter et al., 2013; CC BY 4.0) and the published benchmark tables (RDML consortium).

**Built for qPilot**
- The hardened RDML loader and the SHA-256-pinned downloads.
- The per-well table: parsed by column name, names checked, cached by content hash.
- Quantities, expression-defined groups, the geNorm implementation, the contrast with its confidence interval and stated rule.
- The decision space of 186 analyses that the core sweeps.
- The validation script and its generated table.

## Results and RDML

qPilot reads RDML, and the Analysis Record keeps the input file byte for byte. It does **not** yet write its results back into the RDML file; that is on the roadmap. LinRegPCR can already update the RDML object it analyses, so any RDML-aware tool could then read qPilot's numbers. Instrument desktop software exports RDML but generally cannot import it, so results will not flow back into the instrument's own software either way.
