# qPilot threat model (one page)

qPilot is local research software. It reads a qPCR export (RDML), analyses it deterministically, shows the scientist the choices that can change a conclusion, records their decisions, and offers the same functions to AI agents over MCP (stdio). The scientist uses it through **one page**: `qpilot app` starts one local server (FastAPI, on `127.0.0.1`) that serves the page, its JSON API and a live event stream, over the same on-disk store the MCP server writes. It is **not** for clinical or diagnostic use and is **not** a multi-user service.

## Assets
| Asset | Why it matters |
|---|---|
| Raw curves and sample/target names in the input file | May be unpublished or patient-derived |
| The decision log (`decisions.jsonl`) and the Analysis Record | The evidence of who chose what and why |
| The Studio inbox (`sessions/<input_sha256>/proposals.jsonl`) | What the AI proposed and what a person accepted; the engine builds its design from accepted proposals only |
| The pseudonym key (`sessions/<input_sha256>/.keys/hmac.key`) | Whoever holds it can confirm a guessed sample name behind a token |
| The numbers (`results.json`, `facts.json`) | What a paper or a reviewer relies on |
| An API key for a frontier model (if used) | Spending and account access |
| The launch key (`/?token=…` link, the `qpilot_token_<port>` cookie) | Whoever holds it can use the page's API for as long as that launch runs, including making the decisions only a person may make |
| Uploaded input files (`studio-inputs/` next to the study store) and the exports (`exports/` next to the study store: Prism bundles and Analysis Records) | Unpublished or patient-derived data, kept on disk so a session finds its file again after a restart and a person keeps their files |
| The user's filesystem | An agent, a web page or an uploaded file must not be able to read arbitrary files through qPilot |

## Trust boundaries
```
RDML file (untrusted) ─▶ io (hardened loader) ─▶ engine (qpcr + core, no network, no model)
                                                      │
                                                      ▼
                                        core/store.py: the only writer to a workspace
                                       ┌──────────────┼───────────────────────────┐
                                       ▼              ▼                           ▼
                   the one server on 127.0.0.1    MCP server (stdio)       ai/ → model endpoint
                   (the scientist's browser)      (any agent; untrusted)   (only if chosen)
                   Guard: Host · launch key ·
                   same-origin writes · headers
                   → page · /api · /api/events
```
**Untrusted inputs:** RDML content (including names inside it), sample sheets, every MCP tool argument (including every field of a proposal), every model output, a record zip received from someone else, and every HTTP request to the server (its `Host`, `Origin` and `Referer` headers, query strings, JSON bodies, uploaded files and their file names). A request from the user's own page is trusted only as far as the launch key and the same-origin check go (rows 13 and 24); what it asks for is still checked by the same code the command line and the MCP server use.

## Out of scope
A compromised host or Python environment; another program running as the user that can read the terminal, the browser's cookies or a process's memory (it can use the launch key, row 24); a malicious lab profile written by the user themself; proving who authored a record (signatures are roadmap); multi-user hosting, accounts and roles; 21 CFR Part 11; clinical or diagnostic use.
