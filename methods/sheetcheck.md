# Method card: Spreadsheet Check (recompute a lab's own ΔΔCq sheet)

**What it answers.** Does an analysis that already exists as a spreadsheet follow from its own Cq values, and if not, which step is the first to differ and which known slip reproduces it? A supervisor checking a student's sheet gets "*k* of *n* fold changes reproduce; *m* differ, *j* with a named cause", the first column and row to look at, and, when the arithmetic is right but qPilot's own analysis of the same study disagrees, a hand-over to the robustness grid.

**References.** Livak KJ, Schmittgen TD. *Analysis of relative gene expression data using real-time quantitative PCR and the 2^-ΔΔCT method.* Methods 25(4): 402–408 (2001). Pfaffl MW. *A new mathematical model for relative quantification in real-time RT-PCR.* Nucleic Acids Research 29(9): e45 (2001). The slips are the practitioner errors collected in `research_notes/qPilot niche discovery and features/W2-practitioner-voice.md` (items 21, 62, 64, 66, 68).

**Implementation.** `qpilot/qpcr/sheetcheck.py` (`guess_mapping`, `check_sheet`, `check_sheet_store`, the path functions, `METHOD_CARD`); text in `qpilot/explain/sheetcheck_text.py` (`sheetcheck_v1`, `sheetcheck_findings_v1`, `sheetcheck_handover_v1`). Deterministic engine code: no model call, no network. The file is never edited; only its sha256 is recorded.

| Step | Definition |
|---|---|
| Read | `.xlsx`/`.xlsm` and `.csv`/`.tsv`/`.txt` through `qpilot/io/sheets.read_sheet` and its caps (5 MB file, 20,000 rows, 200 columns, 1,000,000 filled cells, zip-bomb checks). openpyxl (an optional extra, MIT licence) opens workbooks in data-only mode: a formula cell gives the value the spreadsheet program cached when it saved. A workbook with formulas but no cached values (written by openpyxl, pandas or a LIMS export that does not calculate) is refused with a message saying to save it in a spreadsheet program or export CSV; no formula is evaluated |
| Map | `guess_mapping` reads the header row (the row among the first 30 that names a sample column and the most roles) and gives every column a role with a confidence: sample, group, biological unit, gene, well type (no-template and standard rows are left out), Cq (well or mean), mean Cq, ΔCq, ΔΔCq, fold change / RQ / 2^-ΔΔCq, group mean fold change, SD, SEM, p. *Wide* sheets have one Cq column per gene (replicate columns `GAPDH Ct 1`, `GAPDH_2` are one gene; gene names may sit in the row above a "Ct  ΔCt  ΔΔCt" header); *long* sheets have a gene column, and reference genes are rows of the same sample. A log2 fold-change column is read as −ΔΔCq. Reference genes are recognised by name (GAPDH, ACTB, HPRT1, SDHA, UBC, 18S, …) or a header word ("ref", "housekeeping"); the control group by name ("control", "vehicle", "WT", …) or, failing that, as the group whose ΔΔCq averages zero. Rows whose sample cell says "Mean", "SD", "SEM" or "p-value" are the summary rows of the group above. Every output says "mapping guessed, not confirmed" until a person passes a mapping with `confirmed=True` |
| Biological unit | The sample column, or a biological-unit column when mapped; rows of one unit are its technical wells |
| `livak_per_unit` (the textbook path) | Efficiency 2.0. Mean Cq per unit (the geometric mean of the quantities); ΔCq = Cq(gene) − mean Cq of the declared references; calibrator = mean ΔCq of the control group's units; ΔΔCq = ΔCq − calibrator; fold change = 2^-ΔΔCq; a group's fold change = geometric mean of its units' fold changes (the arithmetic mean on the log scale); SD on ΔCq per unit; two-sided t test on ΔCq per unit (Welch's and Student's both count) |
| Conventions accepted | ΔCq written as reference minus target and ΔΔCq written as control minus sample, when the fold change uses the matching sign; an SD in a summary row is checked on the scale of the column above it (ΔCq or fold change); a column with one value per unit is compared per unit, a column that varies within a unit per well |
| Slips (each a pure function of the Cq table) | `sign_inverted` 2^+ΔΔCq · `exponent_twice` 2^FC or 2^-FC (item 64) · `no_reference` no reference subtracted · `wrong_reference` each other reference column, and all of them together · `arith_mean_fc` arithmetic mean of fold changes (item 68) · `stats_on_fc` t test on linear fold changes (item 62) · `wells_as_n` technical wells counted as biological n (calibrator, means, SD, t test) · `row_shift` the value of the previous or next row (a copy-paste offset) |
| Method | `pfaffl`: E_target^ΔCq(control − sample) divided by the geometric mean of the references' ratios, with the efficiencies given (amplification factor per cycle; a reference without one is taken as 2.0) |
| End to end and step by step | Each column is compared with the textbook path from the sheet's Cq values (*end to end*) and with the textbook step applied to the sheet's own previous column (*step by step*). A cell that matches the first is `reproduced`; one that matches only the second `follows` an earlier difference; one that matches neither differs on its own |
| Tolerance | A cell matches when it is within the larger of its column's displayed precision (half a unit in the last decimal shown, read from the decimals present) and 0.5 % relative, with a floor of 1e-9 for arithmetic noise. For delimited files the rounding of every input is carried through each step, because a program writes the values it displays; workbook values are the exact numbers the formulas used, so nothing is carried. A p-value's tolerance includes how far rounded inputs can move it |
| Localise | Columns are walked in step order (mean Cq → ΔCq → ΔΔCq → fold change → group means → SD/SEM → p). The first column that differs on its own, with its first row, is where to look; later columns that only follow it are listed under it (`followed_by`), not reported again |
| Classify | The paths that reproduce *every* cell that differs on its own: one path is `explained`, two or more `ambiguous`, none `unexplained` with the largest gap and whether it is a constant offset |
| Gene names | Each gene name goes through the gene-symbol gate (`qpilot/io/symbols.check_symbol`); names Excel turned into dates or numbers are flagged with the approved symbols they may stand for |
| Hand-over | With the engine's result for the same study (`study=`), a gene whose sheet arithmetic reproduces but whose engine fold change differs by more than 0.5 % is a hand-over, not a finding: what visibly differs (each well's efficiency in the engine, another reference set, other group sizes), both calls under the engine's rule, and a pointer to the robustness grid and the reference-set card |
| Output | `SheetCheckResult`: file sha256, mapping (control named by a cell's text id, never by its label), per-column checks, findings (`kind` "sheet_check", card-shaped for display, but not Decision Cards: nothing in the analysis is decided), localisation per gene, summary, hand-overs and facts `f_sc_*`. `to_json()` is byte-stable. Sample names, group names, header text and the sheet title are never copied into the result |

**On the demo study.** Sheets built from the Vermeulen fixture's own Cq values (347 grouped tumours, MYCN-high 53 against the rest 294 as the engine groups them, references HPRT1, SDHA and UBC, genes ODC1, BIRC5, NTRK1 and CAMTA2): the clean sheet reproduces 1,385 of 1,385 fold changes (347 × 4, less the 5 NTRK1 wells without a Cq, plus two group means) with no finding, in about a third of a second. Each slip planted on one gene is named at its first column with exactly that path, and the other three genes still reproduce: sign inverted, exponent twice and Pfaffl at the fold-change column; no reference and a row shift (row 102 onwards) at ΔΔCq; a wrong reference (HPRT1 alone) at ΔCq; the arithmetic mean at the group means; the t test on fold changes at the p-value. The demo has one well per tumour and gene, so `wells_as_n` is tested on synthetic sheets only. Handed to the engine, all four genes reproduce and differ by method: ODC1 4.44× in the sheet against 3.59× in the engine, BIRC5 5.24× against 4.01×, NTRK1 0.036× against 0.066×, CAMTA2 0.52× against 0.51×, with the same call each time. With the engine's own five references the only cause left is efficiency, and CAMTA2 then crosses the call line (down in the sheet at 0.46×, no call in the engine), as the `ddcq` route in [`routes.md`](routes.md) also finds.

**What is not claimed.** That this is the only tool that recomputes a lab's own sheet and names the wrong step: other tools (Clarida, qRAT, VoilaPCR, AnnealIQ, the TIGEM qPCR tool) have not been checked. That real lab sheets carry these slips at any given rate: the plan's "measure first" step (5–10 real, anonymised analysis sheets) has not been done; every sheet tested here is generated. The check reads one table per sheet; it does not evaluate formulas, read number formats (the precision a person sees in Excel) or follow cell references. A calibrator taken from one sample, paired or one-tailed tests, efficiency-weighted means and other designs are reported as `unexplained` with their gap, not named; so is a Welch p-value from a program that rounds the degrees of freedom, if any does (not checked). A sheet whose fold changes all reproduce can still rest on choices that move the answer; that is what the hand-over and the robustness grid are for.

**Validation.** `tests/engine/test_sheetcheck.py`: synthetic sheets (a clean sheet in CSV and in a workbook, one sheet per slip with its first column, the item-64 "2^10 more mRNA" pattern, wells counted as n in a long per-well sheet, a typo left unexplained, an ambiguous pair, sign conventions, group-level columns, a long per-sample sheet, the method-only hand-over, byte-stable output, no sheet label in the result, date-mangled names in CSV and workbook, refusals of formula-only, oversize and unreadable files, mapping overrides and confirmation, the path functions by hand, the text through the validator) and `demo_data` sheets from the Vermeulen Cq values (the clean sheet, each slip, both hand-overs).
