# 10. Digital PCR (dPCR / ddPCR) analysis: should qPilot extend into it, and how

Researcher note on method (read first). The shared WebSearch budget was exhausted after my first six queries, so everything below comes from direct fetches of primary sources (vendor manuals and PDFs downloaded and text-extracted locally, the RDML schema, GitHub/CRAN/Bioconductor pages and APIs, SEC filings, Zenodo records) plus the Europe PMC records API for papers (DOI lookups and a small number of title lookups; also used for the publication counts). Consequence: I could not gather forum evidence (Reddit, ResearchGate, Biostars); "analysts disagree" is evidenced here from peer-reviewed papers, vendor manuals and GitHub issues, not from forum threads. Facts I only saw in a search-result snippet (not in a fetched document) are marked "(snippet)". Format: the brief's six sections; inside section 1 each key question has Takeaway / Cited findings / Inferences / Gaps as the researcher instructions ask.

Terms for the developers. A dPCR reaction is split into thousands of partitions (droplets on Bio-Rad QX and Stilla; nano-wells on Qiagen QIAcuity; micro-chambers on Thermo Absolute Q). After end-point PCR each partition is read once per colour channel and called positive or negative. With N partitions of which Nneg are negative, the mean copies per partition is λ = −ln(Nneg/N) and the concentration is λ / V, where V is the partition volume [10][12][25]. "Rain" is partitions whose fluorescence sits between the negative and positive clouds [29][54]. "Threshold" is the fluorescence cut-off (1D) or the cluster boundaries (2D, multi-colour) that decide positive vs negative. "Merged wells" / "hyperwells" pool the counts of replicate wells [10][20].

## 1. How this corner of the niche works

### 1.1 Instruments, data formats, raw-data accessibility, software pricing and lock-in

#### Takeaway
Every major platform now exports per-partition fluorescence as CSV (Bio-Rad amplitude export; Qiagen "RFU values" export; Stilla per-droplet values), but each in its own layout, the vendor's own classification is a black box, the native project files (.qlp, .ddpcr, QIAcuity plate archives) are proprietary, and the vendors keep changing constants and column layouts between versions. Only Qiagen exposes a documented API (key-secured "Lab Automation API") that returns results and the rule that set each threshold.

#### Cited findings
- Bio-Rad line-up (vendor page): QX200 2 channels ~20,000 partitions; QX600 6 channels ~20,000; QX700 E/S/HT 7 channels ~17,000; QX Continuum 4 channels ~25,000; QX ONE 4 channels; QXDx AutoDG 2 channels; ">12,000 peer-reviewed publications" feature ddPCR [14]. The QX600 can quantify "12 targets in one well with 6-color detection" [9].
- Bio-Rad software: QX Manager Standard Edition is "free to download after registration"; Premium Edition adds "locked assay protocols with custom calculations, external thresholding algorithms, and detailed reports" plus audit trails and 21 CFR Part 11 tools; experiment types DQ, CNV, MUT, DOF, GEX, RDQ; plex modes Single Target per Channel, Amplitude Multiplex, Probe Mix Triplex [9]. Premium ships with a USB licence key; no price shown [15]. Release notes for QX Manager 2.3.1 (May 2025): Windows 10/11 only; Premium upgrades go through a sales representative [13].
- Bio-Rad formats: QuantaSoft saved `.qlp`; QX Manager Standard opens a `.qlp` and re-saves it as `.ddpcr` ("Contains the results of an experiment run") [10][11]. Per-droplet export: QuantaSoft "Export amplitude data for selected wells to a .csv file (one file for each well)" [11]; QX Manager "Exports amplitude, cluster, and linkage data", where "Export amplitude data" writes "an Excel spreadsheet" with a found/not-found flag and "Export cluster data" includes, per well, target found (1/0), droplet count, mean and SD per dye and the cluster ID [10]. Open tools read these files as `*_Amplitude.csv` with columns `Ch1 Amplitude`, `Ch2 Amplitude`, `Cluster` [35][38]; PoDCall notes QX Manager and QuantaSoft "skip a different number of header lines in the amplitude files", so the importer must know which software produced the file [38].
- Bio-Rad results CSV columns include Poisson 95 % and 68 % CI bounds and, for merged wells, "Total" CI bounds (TotalConfMax/Min, PoissonConfMax/Min, and the same for CNV, Ratio and Fractional Abundance), a `MergedWells` column, `Status` = OK / CHECK / Multi / Manual, and `StatusReason` [10]. A well is CHECK when "the automatic analysis for the well failed or fewer than 10,000 droplets were counted" [10][11]. Auto thresholds for positive-control wells exist from v1.2 but only if the well is typed PosCtrl [10]. "Auto analysis is only available for simplex/duplex experiments" [12]. For Probe Mix Triplex "linear thresholding is not available"; the "Advanced Classification Method" lets the user define up to ten clusters by hand in the 2D plot [10].
- Bio-Rad droplet volume constant: "In QX Manager Software, Version 2.0, Bio-Rad reduced the droplet volume used to calculate concentration from .85 nL to .795 nL. The change resulted in a 7–8% higher concentration in experiments where all other variables were identical ... Beginning with Version 2.1, both the legacy and the new droplet volumes were made available" [10]. QuantaSoft 1.3.2 used 0.91 nL [46].
- Qiagen QIAcuity: instruments One/Four/Eight (1/4/8 plates), 2-plex (2 channels, up to 4-plex) or 5-plex (8 channels incl. 2 hybrid, up to 12-plex), ~2 h per plate; nanoplates 26k (24- or 8-well, 40 µL input) and 8.5k (24- or 96-well, 12 µL); list prices: 8.5k 96-well 10-pack $1,676, 26k 24-well 10-pack $699, 26k 8-well 10-pack $312; intended "for molecular biology applications", with a separate QIAcuityDx for diagnostics [19]. Software Suite calculates with 0.82 nL (26k) or 0.34 nL (8.5k) "in cases where the VPF (volume precision factor) has not been applied. If the VPF has been loaded ... the volume of each well is Nanoplate batch–specific calibrated" [20].
- QIAcuity per-partition export: "Export to CSV ... RFU values" writes one CSV per channel zipped, columns Plate name/ID/type, Well, Sample ID, Sample, Channel (suffix L/H in amplitude multiplexing), Cycled volume (µL, VPF-corrected), Threshold (or Threshold low/high/double), Partition, Is Invalid (up to three codes: Poisson/blistering tests 1–4, reference partition not filled 5/9, dust 6–8, artifacts B/C), Classification, IsPositive, RFU, REF; a "compact" variant drops repeated columns; and: "due to some corrections provided by analysis models, sometimes there might be changes when comparing IsPositive column values with information obtained by comparing RFU values to threshold" [20]. Per-partition RFU CSV export first appeared in Suite v2.0.20 (Nov 2021) "for user designed analysis algorithms" (snippet) [26]. The results CSV ("Current results") carries Partitions valid/positive/negative, Threshold(s), Volume per well incl. VPF, Lambda, actual cycled volume per partition, mean RFU of positives and negatives, threshold strategy and QC-rule outcomes; "From QIAcuity Software Suite version 3.5 onward, CSV export and import files use a new structure" [20].
- QIAcuity thresholding options (v3.5 manual): Auto threshold (default, with ± offset), Numeric, DMM "Delta Min.–Max." ratio "recommended for poorly separated (rainy) assays", DBA "Delta Bandwidth Average" "recommended for well-separated assays", PCT/NCT (positive/negative-control-edge based); thresholds can be propagated from controls to unknowns with the same reaction mix; QC rules: min valid partitions % (default 25 %), expected positive-control concentration range, max positive partitions in NTC; severity Invalidate vs Flag; failures propagate to replicates [20]. Multiple-occupancy export gives counts for every +/− combination up to 8 channels [20]. Multiplexing beyond the standard channels needs a "custom cross talk matrix" built from a training plate of simplexes [20][23][24].
- QIAcuity API: a "Lab Automation API" switched on in the Suite with a generated API key [20]; endpoints include DefineExperimentFromTemplate, AssignAnalysisTemplate (threshold rules incl. AmplitudeMultiplexingAutoThreshold, DynamicThresholdRule, ValidationRules), GetExperimentResults with a per-well, per-channel `thresholdSource` naming the rule that set the threshold, and an events endpoint; applying a template overwrites manual thresholds [21]. 21 CFR Part 11 support (audit trail exported to PDF, electronic signatures on reports) is built into the Suite [22]. The Suite is an 847 MB Windows server install behind a MyQIAGEN login, with browser clients for up to 10 users [78].
- Thermo Fisher Absolute Q (catalog A52864): MAP16 plate, 16 arrays of 20,480 fixed-volume chambers of 432 pL each, "up to four optical channels" (seven dyes listed), results "in as little as 90 minutes", software with 21 CFR Part 11 features; results "can be exported for downstream analysis" (no format named); no price [28].
- Stilla: Crystal Digital PCR partitions a sample on a chip into a 2D droplet array read by a multi-colour scanner; the 2016 paper introduced three-colour detection and discusses "spillover compensation and population identification" as the analysis problems [58]; six-colour systems appear by 2018 (paper title) [58]. The per-droplet fluorescence values are analysed in Crystal Miner [60]; an open R reader for Stilla exports exists (`read_Naica.R`) [30]. Bio-Rad completed the acquisition of Stilla on 30 June 2025 for $166.5 M cash to sellers, $47.6 M debt pay-off, $15 M escrow and $28.6 M fair value of up to $50 M milestones; stillatechnologies.com now redirects to Bio-Rad's digital PCR page [16][17]. Bio-Rad's 2021 acquisition Dropworks (a lower-cost one-step ddPCR device) was impaired in December 2025 ($81.7 M) because "completion of the technology had been delayed" [17].
- RDML and rdmlpython: the dPCR import in rdmlpython (`import_digital_data`) accepts three overview formats, "RDML", "Bio-Rad" (columns Sample, Target/Assay, TargetType/TypeAssay, CopiesPer20uLWell, Positives, Negatives) and "Stilla" (SampleName, Blue/Green/Red_Channel_Target, _Concentration, _NumberOfPositiveDroplets, _NumberOfNegativeDroplets); when no volume is supplied it writes 0.7 nL (RDML), 0.85 nL (Bio-Rad) or 0.59 nL (Stilla) [6].

#### Inferences
- The per-partition CSV is the only vendor-neutral raw data worth building on; `.qlp`/`.ddpcr` and QIAcuity archives should be treated as opaque. A plugin needs three importers (Bio-Rad amplitude/cluster CSV with QuantaSoft vs QX Manager header variants; QIAcuity RFU zip incl. Is Invalid codes; Stilla per-droplet CSV) plus the vendors' results CSVs for cross-checking.
- Vendor calls are not pure thresholds (QIAcuity's IsPositive can differ from RFU-vs-threshold; Bio-Rad's auto algorithm is undisclosed), so the vendor call must be stored as one more "method" rather than as truth.
- Lock-in is mostly on the control/acquisition side (Windows-only control software, licence keys, login-gated downloads), not on the data: the exports are open enough for a local-first tool.

#### Gaps
- Roche Digital LightCycler: all product-page guesses returned 404 and the literature API found zero title hits; nothing verified. Thermo Absolute Q: export file format and whether per-chamber data are exported are unverified. Bio-Rad "external thresholding algorithms" (Premium) mechanism is undocumented in anything I could read (the Premium guide exceeds the fetch size limit). Instrument prices are not public. The exact per-partition CSV column layout of QX Manager (vs QuantaSoft) was not read from the manual itself; it is documented via PoDCall/ddpcr importers [35][38].

### 1.2 dMIQE 2020: items, machine-checkability, adoption

#### Takeaway
dMIQE2020 is a single "essential items only" checklist (9 sections, ~55 items). The nine "Data analysis" items are exactly what an analysis record can fill automatically; the specimen, extraction and oligo sections can never be inferred from instrument files. It recommends RDML as the data-transparency vehicle; adoption numbers do not exist, but the EMMI authors found most environmental qPCR/dPCR papers do not report the necessary controls.

#### Cited findings
- dMIQE2020 (Clin Chem 2020, 401 citations by Oct 2026 per Europe PMC) notes that "data analysis steps, including threshold setting, can be difficult" and provides "a simplified dMIQE table format" [1][67]. Body text: reports "should include the method of manual threshold setting"; manual thresholding "can introduce operator bias", analysis "by multiple operators is preferred"; automated methods "are only valid if the data fit the assumed distribution" (a Kolmogorov–Smirnov check is suggested); excluding rain "can cause negative bias"; "Independent validation experiments have revealed that the partition volumes are not constant" and volume variance biases results more at λ > 2; data should be shared "preferably as Supplemental manuscript files" or in a repository such as RDMLdb; "The latest 1.3 version of RDML ... now includes dPCR data" [1].
- The checklist (XLSX on rdml.org) sections: 1 Specimen, 2 Nucleic acid extraction, 3 NA assessment and storage, 4 NA modification, 5 Reverse transcription, 6 Oligonucleotide design and target information, 7 dPCR protocol, 8 Assay validation (optimisation; analytical specificity and limit of blank; LoD and how evaluated; inhibitor testing), 9 Data analysis: experimental design; negative and positive controls; "Partition classification method (thresholding)"; example positive/negative results incl. fluorescence plots; technical replication; repeatability; reproducibility; "Number of partitions measured (average and standard deviation)"; "Partition volume"; "Copies per partition (λ or equivalent) (average and standard deviation)"; "dPCR analysis program (source, version)"; normalisation method; statistical methods; "Data transparency" (raw data uploaded / supplemental / on request / not available) [2].
- EMMI guidelines (ES&T 2021, 182 citations) for environmental qPCR/dPCR: "many researchers are not reporting necessary and sufficient controls and methods"; provides an element checklist and a controls terminology [56][67].
- The original 2013 dMIQE has 652 citations [3][67]. I found no paper measuring compliance with dMIQE (Europe PMC abstract search for dMIQE + compliance/adherence/survey: 0 hits) [67].

#### Inferences
- Machine-checkable from per-partition exports plus the record: items in section 9 except "experimental design" prose, plus section 8's LoB/LoD if NTC/blank runs are in the record, plus instrument model and software version (section 7, if captured from the export header). Never machine-checkable: sections 1–6 (specimen, extraction, storage, RT, oligo sequences) and reagent lots.

#### Gaps
- No adoption statistics for dMIQE; no journal mandates found.

### 1.3 The analysis decisions people struggle with

#### Takeaway
The literature has produced at least six incompatible rules for the same per-partition data (vendor auto threshold; k-means with ±3 SD rain exclusion; NTC-based extreme-value threshold; kernel-density "cloudy" threshold with rain counted positive; two-component Gaussian mixtures; probabilistic Umbrella), the vendors have each added their own multi-option menus, and every published comparison agrees on two things: the choice matters most at low copies and with rain, and the Poisson CI printed by vendor software understates the real uncertainty. On top of that the partition volume constant, which multiplies every result, has been changed by the vendor (0.91 → 0.85 → 0.795 nL) and measured 13–16 % lower than stated by independent labs.

#### Cited findings (thresholds and rain)
- Jones 2014 (definetherain): "the delineation between positive and negative responses is not always clear"; a k-means cut-off on a positive control, then positives above (positive mean − 3 SD), negatives below (negative mean + 3 SD), rain in between excluded; V = 0.91 µl [sic] in the web tool [31]. Trypsteen 2015 (ddpcRquant): the normality assumption behind existing methods "does not likely hold true for most ddPCR runs, resulting in an erroneous threshold"; threshold from extreme-value modelling of NTC negatives, with per-sample baseline shifts [32]. Dreo 2014: compared QuantaSoft, definetherain and manual thresholds; for one assay "the analysis approach had little influence", for the other "a high global threshold was necessary to exclude false-positive reactions" [34]. Lievens 2016: KDE-based populations, threshold "as close to the negative cloud as reasonably possible", rain "should be counted as positive" because it tracks target and shrinks with more cycles; rule of thumb rain < 2.5 % and resolution ≥ 2.5; "not all software may provide the user with density plots or the ability to edit/export fluorescence values"; Poisson CIs from dPCR software "underestimate total variability", replicate-based intervals recommended [29]. Jacobs 2017 (Umbrella): "misclassification has a major impact on the concentration estimate ... the uncertainty of this classification is typically ignored"; a model-based partition-level probability of being positive gives "a more realistic measure of precision" [33]. Jacobs 2014: "suboptimal thresholds reduce the accuracy of concentration estimates considerably"; "We call on manufacturers to provide sufficiently detailed output data" [44]. Vynck et al. 2023 (Clin Chem review "Digital PCR Partition Classification"): "An overview of these partition classification methods is lacking and their comparative properties are often unclear, likely impacting the proper application of these methods" [41].
- Vendor behaviour: QuantaSoft/QX Manager mark a well CHECK when auto-analysis fails or < 10,000 droplets, and ask for a manual threshold [10][11]; Bio-Rad's own guide claims that for well-separated clusters "A precision of ±5% is maintained regardless of the thresholding method used" [12]; QIAcuity ships five threshold methods plus control-propagation and fallbacks, and explicitly recommends one method "for poorly separated (rainy) assays" [20]. Rowlands 2019 (ctDNA): "Thresholds were manually set for each sample using acceptance criteria defined during the optimisation of each assay"; rain "generally due to a poorly optimised assay"; false-positive droplets "can vary significantly depending on the base change and sequence context" [54]. PoDCall 2023: QuantaSoft "can fail setting accurate thresholds"; "shifts in the negative baseline distribution across wells" and destroyed droplets degrade it; lack of methods "has resulted in users processing the data manually at the expense of standardization" [38].

#### Cited findings (counts, Poisson CI, merged wells, replicates)
- The vendor result tables give Poisson 95 %/68 % bounds and, for merged wells, "Total" bounds; wells merge only when Sample Name, Experiment and Assay match [10][11]. QIAcuity "hyperwells" group wells with identical reaction mix [20].
- Vynck 2016: vendor suites "are typically black-box tools"; they "do not allow the user to analyze more complicated experimental setups such as the correct use of technical replicates or the use of multiple reference loci for determining CNVs"; GLMMs are proposed, and pooling replicate counts is argued against [40]. Burdukiewicz 2016: comparing λ across runs is a multiple-comparison problem; GLM and multiple-ratio tests with Wilson CIs and Dunn–Šidák adjustment, in dpcR [39]. Dube 2008 gives the classic binomial CI and CNV CI maths [50]; Majumdar 2015: optimal precision near λ ≈ 1.59, with dynamic range and dilution framework [51]; Tzonev 2018 defines LoB/LoD/LoQ for dPCR counting statistics [53].
- Lievens 2016 post-run criteria: fraction of sample compartmentalised ≥ 30 % for quantification down to 1 % (50 % for 0.5 %) [29]. Bio-Rad: minimum 10,000 accepted droplets for auto-analysis [10]. QIAcuity: minimum valid partitions % rule, default 25 % [20].

#### Cited findings (partition volume and inter-instrument comparability)
- Pinheiro 2012 (NRC Canada): relative expanded uncertainty < 5 % for ddPCR copy concentration after independent volume work [48]. Dong 2015: relative uncertainty of partition volume 0.7 % (BioMark), 0.8 % (QX100), 2.3 % (QuantStudio 12k), 2.9 % (RainDrop); plasmid conformation affected droplet platforms; after volume correction all four agreed with the certified value [45]. Košir 2017 (inter-laboratory, SI-traceable microscopy): QX100 and QX200 AutoDG droplets "significantly lower droplet volumes (13.1%, 15.9%, respectively) than stated by the manufacturer", with supermix-dependent differences; "the droplet volumes should be assessed for each system" [46]. Emslie 2019: mean droplet volume 0.786 nL over 39 weeks, intermediate precision 1.7 %, skewed intra-well distributions bias concentration, mastermix proportion and a 10 % pipetting error change volume [47]. Talanta 2020 inter-laboratory ctDNA study: "a systematic error caused by uncorrected droplet volume in Naica Crystal ddPCR platform was found"; between-laboratory consistency "greatly improved when a correct droplet volume was applied" [59].
- Platform comparisons 2023–2025: QX200 vs QIAcuity duplex GMO assays both met JRC acceptance criteria [61]; QX200 vs Absolute Q ctDNA concordance > 90 %, "ddPCR exhibited higher variability and a longer workflow" [62]; qPCR, LOAA and QX200 fully concordant for FCGR3B CNV [63]; Naica, QX200 and LOAA compared for a species marker [60].

#### Cited findings (multiplexing)
- Whale 2016: 2-channel duplex gives four clusters; competing duplexes make the double-positive cluster "form an arc"; amplitude/probe-mix multiplexing and drop-off assays described; "for all the dPCR platforms it is possible for the user to manually set the threshold" [42]. Dobnik 2016 (4-plex GMO): "sixteen clusters of droplets ... may appear"; "Current version of QuantaSoft software does not enable the analysis of more than four clusters of droplets at once, therefore the analysis ... can be cumbersome and time consuming as two individual exports need to be done and afterward additional calculations must be performed in another software"; they built a Shiny tool [43]. Brink 2018 (ddPCRclust): "algorithms for automated analysis of non-orthogonal, multiplexed ddPCR data are unavailable"; ensemble of flowDensity, SamSPECTRAL, flowPeaks with the Hungarian method for label assignment, adjusted Rand index as confidence; agreement with expert annotation ARI 0.997 on eight reactions; "minutes rather than hours"; "very sparse clusters from low DNA concentration remain challenging" [37]. Qiagen 12-plex: amplitude multiplexing needs "three sharp clusters of positive signal" per channel and "In some instances multiple thresholds could not be set" until a custom cross-talk matrix was applied [24]. Stilla: multicolour needs "spillover compensation and population identification" [58].

#### Cited findings (LoB/LoD/LoQ, false positives)
- Milbury 2014: LoD process for EGFR assays; measured false-positive rate one in 14 million for L858R, "which indicates the theoretical LoD if an unlimited amount of DNA is evaluated" [52]. Kaudela 2026 (Anal Chem): "the limit of blank varied up to 4-fold between different PCR reagent lots, substantially affecting limit of detection estimates"; they conclude the method "needs the establishment of lot-specific LOBs and LODs"; thresholds set manually between clusters using the positive control; LoB per CLSI EP17-A and ISO 20395:2019 [55]. Talanta 2020: LoB/LoD/LoQ 0.01 %/0.02 %/0.1 % mutant fraction [59].

#### Inferences
- The disagreement is structural, not sloppy: "rain = positive" (Lievens) and "rain = excluded" (definetherain) are both published and both still used. A tool that reports how many reasonable classifications agree is the honest answer, and this is exactly qPilot's robustness engine applied to partitions instead of curves.
- The decisions that flip conclusions are few and locatable: wells near LoB/LoD (positives ≤ a handful), CNV ratios near integer boundaries, mutant fractions near a clinical cut-off, and any well with > 2.5 % rain or resolution < 2.5. Everything else is insensitive (Bio-Rad's ±5 % claim [12]). That is a textbook Decision-Card situation.
- Partition volume is a "silent constant": the same export reanalysed in QX Manager 1.2 vs 2.0 differs by 7–8 % [10]; QIAcuity applies batch-specific VPF only if the user loaded it [20]. Any cross-study or cross-platform comparison must record the constant used.

#### Gaps
- No peer-reviewed inter-operator threshold variability study found (Europe PMC title search returned nothing). No forum evidence (budget). No published head-to-head benchmark of all threshold tools on one public dataset; the 2023 Clin Chem review says comparative properties are "often unclear" [41].

### 1.4 Open tools, licences, maintenance, standards

#### Takeaway
The open dPCR tool landscape is small, R-only, mostly GPL, mostly single-plate, and mostly unmaintained; the one Apache-2.0 algorithm (Lievens' "cloudy") comes with the best public per-droplet dataset. No Python package exists under any obvious name. RDML 1.3 (Oct 2022) defines dPCR storage (partition counts in XML, per-partition end-point fluorescence as TSV sidecars) and rdmlpython, qPilot's existing dependency, already reads Bio-Rad and Stilla overview files and writes partition tables.

#### Cited findings
- ddpcr (CRAN 1.16.0, 2026-01-14, MIT; 66 stars; 79,523 CRAN downloads since 2015, 763 last month): automatic gating only for PN/PP-type plates (FAM+/FAM+HEX+); pipeline: drop wells < 5,000 droplets, IQR outlier removal, 2-component Gaussian mixture for empties (mean + 7 SD), rain = below (filled mean − 3 SD), KDE gate on HEX for mutant/wildtype, binomial test vs 1 %; input `*_Amplitude.csv` from QuantaSoft; closed issues are almost all dplyr/ggplot2 breakages; input is CSV only "since the proprietary raw format is readable only by QuantaSoft" [35][68][75].
- twoddpcr (Bioconductor 1.14.0, GPL-3; last push Feb 2021; 2,184 distinct-IP downloads in 2025): k-means, SD-rain, Mahalanobis rain; Poisson with V default 0.85 nL; KRASdata example; open issue #3 "Support for multiple ddPCR plates" (Aug 2019, no maintainer reply): "I cant analyse all the experiments at once on twoddPCR" [36][69][75].
- ddPCRclust (Bioconductor 1.32.0, Artistic-2.0; last push Oct 2019; 2,176 distinct IPs 2025): ensemble clustering for up to four targets in two channels; eight example per-droplet CSVs plus a template [37][69][75][76].
- PoDCall (Bioconductor 1.20.0, GPL-3; push Aug 2026; 1,467 distinct IPs 2025): Gaussian mixtures per well with permutation LRT for component count, IQR outlier rule (Q = 9), reference-well baseline shift; reads QuantaSoft or QX Manager amplitude files; V = 0.851 nL; five example wells; open issues ask how to adjust the threshold and for a QX Manager sample-sheet example [38][69][75].
- dpcR (CRAN 0.6, 2025-06-18, GPL-3; reads QX100/QX200 and BioMark; GLM/MRT comparisons, simulations, dpcReport GUI; 33,092 downloads since 2015) [39][68].
- Gromgorgel/ddPCR (Apache-2.0; push Feb 2024): the "cloudy" algorithm (threshold, populations, resolution, % rain, % compartmentalisation), threshold modes cloudy / gev (Trypsteen) / mixed / manual, EvaGreen cross-talk correction, readers for QX and Naica exports, a Shiny GUI, and `Dataset.zip` (22.6 MB): 472 reactions from 9 plates, up to 16,985 droplet fluorescence values per reaction, with per-reaction metadata (primer/probe concentration, annealing temperature, touchdown, enhancer, cycles, sonication) [30][75].
- definetherain: MIT JavaScript, browser-local, last push 2019 (fork) / 2014 (original) [31][75]. ddpcRquant: web tool at UGent, licence not stated, "A new ddpcRquant update will come out 2022" with no later date [32]. Umbrella: "An R implementation ... is available" [33], location not found. Dobnik's ddPCRmulti Shiny tool: bit.ly link only [43].
- Python: PyPI has no `ddpcr`, `dpcr`, `pydpcr`, `ddpcrpy`, `digitalpcr`, `dpcr-tools` or `ddpcr-tools` (all 404 on the JSON API, 17 Oct 2026) [75].
- RDML: dPCR "is only supported from RDML version 1.3 onwards" [5]; v1.3 Recommendation dated 26.10.2022 [4]; changes file: partition counts live in the XML, per-partition values in tab-separated table files "stored in a partitions folder within the RDML zip file", one column pair per fluorescence (value + score p/n/u/e), new `partitions` element with `volume` (average partition volume in nL), optional `endPtTable` filename, and `data` entries per target with `pos`, `neg`, optional `undef`, `excl`, `excluded` reason and `note` [4]. rdmlpython (MIT; push May 2026) implements `import_digital_data` (formats RDML, Bio-Rad, Stilla), `get_digital_overview_data`, `get_digital_raw_data`, and migrates between 1.3 and 1.4 [6]. The Rust crate rdml-qpcr (MIT/Apache-2.0, Oct 2026) reads 1.0–1.4 and models `Partitions`, `PartitionData` and TSV `PartitionTable`s [7]. rdml.org lists no dPCR vendor among compliant software (Clarida, Primer3Plus, RDMLdb, LinRegPCR, R and Mathematica packages) [8]; RDML-Tools (gear-genomics) requires v1.4 but documents no dPCR analysis [5].
- Standards used by practitioners: dMIQE 2013/2020 [1][3]; EMMI 2021 [56]; ISO 20395:2019 (qPCR and dPCR quantification-method performance) is cited as the validation framework in 2026 dPCR papers [55][57]; CLSI EP17-A for LoB/LoD [55]; JRC/ENGL guidance for GMO dPCR validation [61]; EuroMRD: "no established guidelines for ddPCR MRD analysis and data interpretation have been defined ... a major standardization effort is underway" (2022) [66].

#### Inferences
- Licence map for a permissive Python plugin: port the maths from papers (all methods are described in enough detail), reuse the Apache-2.0 cloudy code and Lievens dataset directly, use scikit-learn/scipy (BSD) for GMM, KDE, k-means and GEV; do not vendor twoddpcr, dpcR or PoDCall (GPL-3). ddPCRclust's own licence is Artistic-2.0 but its dependencies' licences were not verified.
- RDML 1.3 is sufficient as the dPCR record container (partition counts + sidecar tables + volume), and qPilot's existing rdmlpython path makes this nearly free.

#### Gaps
- Licences of flowDensity/SamSPECTRAL/flowPeaks unverified. Umbrella's code location unverified. Whether RDML-Tools' editor can import dPCR vendor files: not documented.

### 1.5 Market, users, growth by application

#### Takeaway
dPCR is roughly 4 % of PCR literature but growing ~25 % year-on-year in 2025 while qPCR is flat; the fastest-growing platforms in publications are QIAcuity, Absolute Q and QX600. Vendors' own numbers say growth is consumables-led (Qiagen), while Bio-Rad is consolidating (bought Stilla, wrote off Dropworks). Liquid biopsy/ctDNA, methylation, cell and gene therapy, MRD and wastewater are the largest application communities.

#### Cited findings (Europe PMC hit counts, 17 Oct 2026; mentions in indexed title/abstract/full text; rough proxies, not curated counts) [67]
- dPCR vs qPCR records per year: 2012: 99 vs 32,830; 2016: 911 vs 50,181; 2020: 2,523 vs 79,274; 2023: 3,293 vs 82,438; 2024: 3,308 vs 83,573; 2025: 4,104 vs 96,639.

## 3. Discoveries (ranked by impact × feasibility × fit)

### D1. "Classify it every reasonable way": a partition-level dPCR plugin whose output is agreement, not a threshold

1. Persona and situation. A postdoc or core-facility analyst with a QX200/QX600 or QIAcuity plate of 24–96 wells of cfDNA, FFPE, eDNA or wastewater extracts, weekly. Several wells show rain or only a few positive droplets; the vendor software flags CHECK or asks for a manual line; the lab's SOP says "set thresholds manually using the positive control" [54][55].
2. Evidence of pain. P1, P2, P4 above: dMIQE calls thresholding "difficult" and warns of operator bias [1]; Jacobs 2014 shows thresholds "reduce the accuracy of concentration estimates considerably" and asks vendors for raw output [44]; the 2023 Clin Chem review says comparative properties of classification methods are "often unclear" [41]; the published methods contradict each other on rain [29][31][33]. Cost estimate (mine): manual thresholding of a 96-well plate with rain is tens of minutes to hours [37]; a wrong call at LoD is a wrong "detected".
3. What exists today. Vendor auto-threshold (undisclosed), QIAcuity's five methods [20], six R tools (GPL/Artistic, single plate, 2-channel, 2014–2021) [31][32][33][35][36][37][38]. None re-runs the plate under all methods, none quantifies how much the conclusion depends on the choice, none writes the choice into a re-runnable record.
4. Concrete feature. Input: per-partition exports (Bio-Rad `*_Amplitude.csv` incl. `Cluster`, QuantaSoft and QX Manager header variants [35][38]; QIAcuity "RFU values" zip incl. `Is Invalid`, `IsPositive`, `Threshold`, `Cycled volume` [20]; Stilla per-droplet CSV via the read_Naica layout [30]) plus the vendor results CSV (positives, negatives, threshold, volume, CI) [10][20]. Deterministic method grid per well and channel: (a) vendor call as recorded; (b) KDE populations with kurtosis-scaled bounds and rain counted positive (cloudy, port from Apache-2.0 code [29][30]); (c) NTC-based GEV threshold with baseline shift (ddpcRquant maths [32]; `scipy.stats.genextreme`); (d) k-means 2/4 clusters ± 3 SD rain exclusion (definetherain [31], twoddpcr [36]); (e) two-component Gaussian mixture with mean + k·SD empties and rain band (ddpcr/PoDCall maths [35][38]; scikit-learn); (f) partition-level posterior probability of positivity with NTC-shaped negatives (Umbrella [33]) giving a probabilistic concentration and CI. For each: λ, concentration under the recorded volume, binomial/Poisson CI [50], and QC facts (resolution, % rain, % compartmentalised, λ-in-range [29]). Robustness fact: "k of 6 classifications put well A03 above LoD / give CNV = 3 / give MAF > 0.1 %". Decision Card only when the grid disagrees on a conclusion-level fact (positive/negative call, integer CN, MAF above cut-off, ratio outside spec), with the 1D/2D plot, the per-method calls, the consequences per sample and a recommendation (for example "well is rainy (4.1 % rain, resolution 2.1): methods that count rain positive give 12 copies/µL, those that exclude it give 7; NTC supports the GEV line; choose and record"). Record: per-well thresholds/clusters per method, chosen method and reason, in RDML 1.3 `partitions` (pos/neg/undef/excl per target, `volume`, `endPtTable` with the per-partition table and p/n/u/e scores) [4][6]. MCP: `dpcr_classify(study, well, method)`, `dpcr_robustness(study)`, `dpcr_decide(card_id, option, reason)`, reusing the existing qpcr_* contracts.
5. Feasibility. Datasets: Lievens 472 reactions with designed rain/anneal/cycle gradients (Apache-2.0) [30]; ddPCRclust 8 multiplex wells [76]; ddpcr 5 wells [35]; PoDCall 5 wells [38] (GPL package, data use for tests only); twoddpcr KRASdata [36]. Libraries: numpy/scipy/scikit-learn (BSD), rdmlpython (MIT) [6]. Methods with DOIs: [29][31][32][33][35][38][50]. Effort (estimate): importers 3–5 days; five classifiers + facts 1–2 weeks; cards/robustness wiring reuse the core, 1 week; acceptance tests against vendor results CSV and the Lievens set, 1 week. Hardest part: 2D/multi-colour classification (see D4) and faithfully reproducing QIAcuity's invalid-partition semantics (treat `Is Invalid` as excluded, never re-score).
6. Why qPilot. This is the robustness engine and Decision Cards with "partition table" in place of "amplification curve"; the record, hash chain, MCP and autonomy levels are unchanged; rdmlpython already has the dPCR data model [6].
7. Risks. Vendors' auto-threshold is undisclosed, so "vendor call" is only reproducible from the export, not recomputable; without forum evidence the size of the manual-threshold pain is inferred from papers and vendor UI (CHECK status) rather than from users; a lab may trust only the vendor number for regulated work (out of scope anyway). Confidence: high that the pain exists and is unsolved; medium on how many research users will adopt an external tool.

### D2. The constants ledger: "same counts, different answer" made visible (partition volume, dilution, reaction volume)

1. Persona and situation. A PI comparing this year's QIAcuity data with last year's QX200 data, a reference/GMO lab transferring an accredited assay between platforms [61], or a core facility that upgraded QX Manager from 1.2 to 2.x.
2. Evidence of pain. Bio-Rad changed its droplet volume from 0.85 to 0.795 nL in QX Manager 2.0 "resulting in a 7–8% higher concentration in experiments where all other variables were identical" and now ships both [10]; QuantaSoft 1.3.2 used 0.91 nL [46]; independent labs measure 0.786 nL [47] and 13–16 % below the stated value [46]; QIAcuity uses 0.82/0.34 nL unless a batch VPF is loaded [20]; an interlaboratory study found "a systematic error caused by uncorrected droplet volume in Naica" [59]; open tools hard-code 0.85 [36], 0.851 [38], 0.91 [31], 0.7/0.85/0.59 [6]. dMIQE2020 requires "Partition volume" and "dPCR analysis program (source, version)" [2].
3. What exists today. A dropdown in QX Manager 2.1+ [10]; the VPF upload in QIAcuity [20]; nothing that stores which constant produced a number or recomputes a study under alternatives.
4. Concrete feature. Every concentration in the record is derived from (positives, negatives, valid partitions) × a named `volume_constant` fact with provenance (vendor-export value, software version, VPF batch, or a literature measurement with DOI). Robustness axis "partition volume ∈ {export value, legacy vendor value, measured literature value}" with effect size per conclusion; a Decision Card only when the choice crosses a boundary (integer CN, LoQ, a specification limit, cross-platform agreement). Cross-platform studies get a "platform-comparability" fact (ratio of concentrations under each platform's constant). The methods paragraph and the dMIQE items "Partition volume" and "analysis program (source, version)" are filled from these facts. MCP: `dpcr_recompute(study, volume_nl=…)`.
5. Feasibility. Pure arithmetic on existing facts; literature constants with DOIs [45][46][47][48]; QIAcuity's `Cycled volume` and `Actual cycled vol/partition` columns [20]; Bio-Rad's documented constants [10]. Effort (estimate): 2–3 days. Hardest part: convincing users this matters; the evidence table above is the argument.
6. Why qPilot. "No naked numbers": the engine already binds every number to a fact id; adding a constant fact with provenance is native. The record makes the choice auditable years later.
7. Risks. Vendors may object to "recomputed" values; mitigate by always showing the vendor value first and labelling alternatives. Confidence: high (facts are documented by the vendors themselves).

### D3. Study-level uncertainty and lab memory for dPCR: replicate-aware CIs, merge policy, and lot-specific LoB/LoD

1. Persona and situation. A liquid-biopsy or pathogen lab calling "detected / not detected" on 1–5 positive partitions weekly; a CNV lab calling integer copy numbers from 2–4 replicate wells; an assay developer validating a new reagent lot.
2. Evidence of pain. Vendor CIs are Poisson-only and "underestimate total variability" [29]; vendor suites "do not allow ... the correct use of technical replicates" [40]; LoB "varied up to 4-fold between different PCR reagent lots", requiring "lot-specific LOBs and LODs" [55]; false-positive droplet rates depend on sequence context [54]; LoB/LoD/LoQ definitions for dPCR exist [53][52]; Bio-Rad's merged-well "Total" CI is undocumented beyond its name [10].
3. What exists today. GLMM R code in a 2016 paper [40], dpcR's MRT [39], spreadsheets following CLSI EP17 [55], QIAcuity QC rules "max expected positive partitions in NTC" per plate only [20].
4. Concrete feature. (a) Replicate-aware estimates: binomial GLMM with well random effect (statsmodels, BSD) giving a CI that includes between-well variance, reported next to the Poisson CI as two facts; merge policy as a decision ("pool counts" vs "mixed model") with a card only when the two CIs disagree on a conclusion. (b) LoB/LoD/LoQ engine: from the NTC and negative-control wells across all plates in the study (and, with the lab-memory roadmap item, across studies and reagent lots): LoB = 95th percentile of positive-partition counts in blanks (EP17 style [55]), LoD from positives in low-level samples, LoQ from CV target; facts per assay × lot; a "detected?" Decision Card for any sample whose positives ≤ LoB or within the LoD band, listing the blanks that define it. (c) Study QC facts per well: resolution, % rain, % compartmentalised, λ within the precision-optimal range [29][51]. Record: controls, blanks and their counts are first-class entries (dMIQE "comprehensive details of controls" and "Repeatability/Reproducibility" [2]; EMMI control terminology [56]). MCP: `dpcr_detection_limits(assay, lot)`, `dpcr_call(sample)`.
5. Feasibility. Maths in [40][50][52][53]; statsmodels/scipy (BSD); test data: Lievens' 48 independent dilutions of a soy sample (used for CI testing) [29][30]; wastewater well-level dataset with blanks (Eawag, CC-BY) [70]. Effort (estimate): GLMM + facts 1 week; LoB/LoD engine 1 week; cards 3 days. Hardest part: deciding defaults for LoB when a study has few blanks (surface it as a card rather than guess).
6. Why qPilot. Multi-plate studies are the product's unit of work (vendors and R tools are single-plate [36]); GRADE-style study confidence already exists and gets a dPCR-specific reason set ("LoB from only 3 blanks").
7. Risks. GLMM convergence on sparse counts; users may expect vendor numbers to match exactly (they will, for the Poisson fact). Confidence: high for LoB/LoD, medium for GLMM uptake.

### D4. Multiplex cluster assignment with agreement scores and "orphan partition" cards

1. Persona and situation. Assay developers and GMO/VCN/MRD labs running probe-mix triplex or amplitude-multiplex 3–4-plex on QX200, 6-colour 12-target panels on QX600, or 5-plex/12-plex on QIAcuity; every plate.
2. Evidence of pain. 4-plex gives up to 16 clusters, QuantaSoft handles four, so analysts do "two individual exports" and external calculations [43]; manual multiplex analysis takes "hours" and "very sparse clusters ... remain challenging" [37]; "Auto analysis is only available for simplex/duplex" [12]; Probe Mix Triplex disables linear thresholds and the Advanced Classification mode is fully manual [10]; QIAcuity amplitude multiplexing needs three separable clusters per channel and a training plate for a custom cross-talk matrix, and "in some instances multiple thresholds could not be set" [24][20]; multicolour needs spillover compensation [58]. Both dual-transduced CAR-T VCN [65] and GMO quantification [43] depend on it.
3. What exists today. ddPCRclust (R, 2 channels, ≤ 4 targets, last commit 2019, Artistic-2.0 with GPL-flavoured dependencies unverified) [37]; Dobnik's Shiny tool [43]; vendor manual lassoing [10][11].
4. Concrete feature. Deterministic, seedable ensemble on the n-channel partition table: (i) Gaussian-mixture with the expected number of clusters (2^targets minus impossible combinations), (ii) density-peak / mean-shift, (iii) k-means with geometric initialisation from the single-positive controls; label clusters by the expected geometry (angles from the negative cloud; Hungarian assignment as in [37]); agreement = adjusted Rand index across methods, per partition "orphan" status when methods disagree; spillover/cross-talk correction as an explicit, recorded matrix (QIAcuity exposes CXTM; Stilla "spillover compensation" [58]). Per-target counts and Poisson CIs with and without orphans; a Decision Card for wells where orphan allocation changes a target's call; a "controls geometry" card when single-positive controls are missing (then the labelling is a guess, and the card says so). Record and MCP as in D1 (`dpcr_cluster(study, well)`).
5. Feasibility. Eight annotated multiplex example wells [76] plus Dobnik's and the VCN papers' designs [43][65] for tests; scikit-learn (BSD); the ensemble idea from [37] reimplemented from the paper. Effort (estimate): 2–3 weeks; hardest part: robust cluster labelling with sparse clusters and arc-shaped double-positive clusters [42].
6. Why qPilot. Agreement-as-confidence is the robustness engine; the card for ambiguous partitions is the escalation rule ("conclusion-flipping choices are human").
7. Risks. Hard problem; vendors are improving (QIAcuity 3.x multiple thresholds, QX600 software); licence check for any borrowed code. Confidence: medium.

### D5. dMIQE2020 auto-filled from the record, with an RDML 1.3 dPCR file as the "data transparency" artefact

1. Persona and situation. Any author or reviewer; every manuscript and thesis chapter with dPCR.
2. Evidence of pain. The checklist asks for partition classification method, number of partitions mean ± SD, partition volume, λ mean ± SD, program and version, technical replication, repeatability, reproducibility, controls, statistical methods, data transparency [2]; dMIQE2020 recommends RDML [1]; EMMI finds most papers omit the controls [56]; the 2013 and 2020 guidelines have 652 and 401 citations yet no compliance data exist [67].
3. What exists today. An XLSX to fill by hand [2]; RDMLdb; no software emits dMIQE values; no dPCR vendor is RDML-compliant [8].
4. Concrete feature. A dMIQE2020 table generator: each section-9 item bound to engine facts (method names and versions from D1, counts/λ/volume from the record, controls and replicate structure from the plate layout, LoB/LoD from D3), the remaining items (sections 1–6, lots) presented as explicit "author must supply" fields; export the study as RDML 1.3 with `partitions` elements and `endPtTable` sidecars so the "raw data" item is a single checksummed file [4][6]; the existing methods-paragraph generator covers the prose. Machine-checkable list (from the XLSX): all nine section-9 items except "Description of dPCR experimental design"; section-7 "instrument model" and section-8 LoB/LoD when blanks exist; never: specimen, extraction, storage, modification, RT, oligo sequences, reagent lots [2].
5. Feasibility. rdmlpython already writes the structures [6]; the checklist is public [2]; effort (estimate) 3–5 days once D1 exists. Hardest part: keeping the table honest when a user analysed only part of the study.
6. Why qPilot. The record already carries versions, checksums and decisions; the auto-filled MIQE 2.0 roadmap item becomes dMIQE for free, and RDML export is the existing output path.
7. Risks. Reviewers may not know dMIQE; minimal downside. Confidence: high.

### D6. Application decision packs: CNV, vector copy number, wastewater and GMO as named decision spaces

1. Persona and situation. CNV labs (integer copy calls with one or more reference assays), CAR-T/gene-therapy QC (VCN per cell), wastewater surveillance (EMMI reporting, PMMoV-style normalisation), GMO control labs (JRC acceptance criteria).
2. Evidence of pain. CNV needs a reference assay or reference sample and the formulas are vendor-prose (QIAcuity: CN = (ConcTARGET/ConcREF) × CN of reference; Bio-Rad: CN = (A/B) × NB with NB usually 2) [25][12]; Vynck shows single-reference CNV ignores reference instability and replicate variability [40]; VCN papers add a transduction-efficiency-adjusted VCN using Poisson statistics [64] and multiplex VCN for dual vectors [65]; EMMI prescribes controls and reporting for wastewater qPCR/dPCR [56]; GMO dPCR methods must meet JRC/ENGL criteria and ISO/IEC 17025 [61]; EuroMRD has no ddPCR MRD guideline yet [66].
3. What exists today. Vendor "experiment types" (CNV, GEX, MUT, DOF, RDQ [9]; QIAcuity second-level analyses and hyperwells [20]) inside one plate; application papers' spreadsheets.
4. Concrete feature. A "pack" = a decision space + fact definitions + checklist for one application, run on the engine from D1–D3: CNV pack (reference-assay set × volume constant × classification method grid; integer-call card when the CI straddles n ± 0.5; multiple-reference stability borrowed from the qPCR geNorm logic [40]); VCN pack (vector copies / (reference copies / ploidy); adjusted VCN per [64]; card when transduction efficiency is unknown); wastewater pack (EMMI control set as required facts; per-sample LoD from valid partitions; normaliser choice as a robustness axis) [56]; GMO pack (trueness/precision vs JRC criteria as pass/fail facts) [61]. Each pack produces its own methods paragraph and dMIQE/EMMI table. MCP: `dpcr_pack_run(study, pack)`.
5. Feasibility. Formulas with DOIs [12][25][40][64]; datasets: QIAcuity application guide examples [25], protist CN dataset [70], wastewater dataset [70]. Effort (estimate): 1 week per pack after D1–D3. Hardest part: EuroMRD/MRD has no consensus to encode yet [66]; leave MRD as "facts only".
6. Why qPilot. The domain-agnostic core was designed so plugins add decision spaces; packs are the cheapest way to speak each community's vocabulary.
7. Risks. Scope creep; keep packs declarative (YAML of facts, axes, cards). Confidence: medium–high for CNV/VCN, medium for wastewater, low for MRD.

### D7. Vendor capture for dPCR: QIAcuity Lab Automation API client and per-partition importers (lower priority, enabling work)

1. Persona and situation. Lab-automation engineer or agent-driven workflow with a QIAcuity Four/Eight or a QX200/QX600 feeding a shared workspace.
2. Evidence. QIAcuity's documented, key-secured API (DefineExperimentFromTemplate, AssignAnalysisTemplate with threshold and validation rules, GetExperimentResults with `thresholdSource`, events) [21][20]; the per-partition RFU export is UI-driven (zip per channel) [20]; Bio-Rad has no public API and Premium "external thresholding algorithms" are undocumented [9]; exports change structure between versions (QIAcuity 3.5) [20] and between QuantaSoft/QX Manager [38].
3. What exists today. Vendor UIs; R importers keyed to one layout.
4. Concrete feature. Versioned importers with header fingerprints (QuantaSoft vs QX Manager amplitude/cluster/results CSV; QIAcuity RFU, multiple-occupancy and current-results CSV v3.2/v3.5; Stilla per-droplet CSV); a QIAcuity API client that pulls results and the rule names that set thresholds into the record as "vendor decisions" (so an agent can see that a threshold came from a template rule, not a human); watch-folder ingestion for Bio-Rad.
5. Feasibility. API appendix PDF (129 pages) [21]; manuals [10][20]; effort (estimate) 1–2 weeks; hardest part: no public API test instance; needs a partner lab.
6. Why qPilot. Fits the existing vendor-capture roadmap and the "actor = human/agent/system" contract.
7. Risks. Vendor API changes; QIAcuity-only. Confidence: medium.

## 5. Open questions and what I could not verify

- Forum-level evidence (Reddit, ResearchGate, Biostars) on threshold frustration: not gathered (search budget). The strongest substitutes are the vendor's CHECK status [10][11], PoDCall's and Dobnik's statements [38][43] and the twoddpcr multi-plate issue [36].
- Roche Digital LightCycler: no verifiable source on partitions, channels or exports. Thermo Absolute Q: export format unknown. Bio-Rad QX Manager Premium "external thresholding algorithms": interface unknown (plugin? script? file?); if it is a file-based hook it would let qPilot's thresholds flow back into the vendor software.
- Exact column layout differences between QuantaSoft and QX Manager amplitude exports, and the QX600 six-channel export layout: not read from Bio-Rad documents (the >10 MB guides could not be fetched); known only from importer code [35][38].
- Licences of flowDensity/SamSPECTRAL/flowPeaks (ddPCRclust dependencies) and of Umbrella; whether a permissive port is needed for all three ensemble members.
- Whether RDML 1.4 is a published Recommendation: rdmlpython and the Rust crate implement 1.4 [6][7] and RDML-Tools require it [5], but rdml.org lists only up to 1.3 [4].
- No public QIAcuity per-partition dataset; no inter-operator threshold-variability study; no dMIQE compliance survey; no market-size figures; no installed-base counts.
- Qiagen release-note facts (RFU export introduced Nov 2021; compact export and invalidation reasons June 2022; QC metrics in v3.2; new thresholding algorithms in v3.5) are from search snippets of Qiagen release notes, not from documents I read [26]; the v3.5 user manual confirms the current state [20].
